## 守ること

- このGitHubリポジトリのアプリコードは**ハッカソン開始後に作成する**。前日までの旧モックを完成済みコードとして流用しない。
- 実患者情報を使わない。架空患者、ダミー病院、許可済み教育原稿のみ。教材の出典や許諾を確認してから外部送信する。
- AIは**資料から教材案を作成し、教材の自然言語検索を行う**。AIによる患者への個別医学助言、診察音声の解析、症状の緊急度判定は行わない。
- 医療者が患者を閲覧するには本人認証 + 患者の診察ごとの明示承認 + 有効な60分セッションが必要。病院所属だけではアクセス不可。
- 医療者の教材処方は最終確認必須。共通教材は別人承認、病院教材は承認権限あれば自己承認可。
- 認証/許諾/公開設定は**バックエンドで検証**。フロントの非表示だけで権限管理しない。
- 患者ホームは学習進捗中心、医療者ダッシュボードは質問・誤答・未完了教材中心。
- UIは淡い水彩＋細いネイビーの線画、自然な成人向けの温かみ。デザイン正本は `DESIGN_REFERENCE.png`。画像の無断公開に注意。

## 推奨する進め方

1. リポジトリの状況を確認し、採用技術・DBスキーマ・API認可設計・P0の縦断テストを提案する。
2. 最小の縦断動作を作る：患者ログイン → QR共有 → 医療者承認取得 → 教材処方 → 学習・クイズ → 再診で結果確認。
3. 次に編集/承認・Claude教材生成、教材検索、通知を追加。公開可能なダミーデータを使う。
4. 型チェック、ユニット/統合/E2Eテストを通す。セキュリティテストは `ACCEPTANCE_TESTS.md` を参照。
5. 外部API鍵や許諾原資料はGitに入れない。必要な設定は `.env.example` のダミー名とREADMEに記載。
6. 各機能の実装ステータスをREADMEに更新し、未完成のものを完成と表示しない。

## 初回指示

この文書と `REQUIREMENTS.md`、`DECISIONS.md`、`ACCEPTANCE_TESTS.md` を読み、**まだコードを変更せず**実装フェーズ、アーキテクチャ、データモデル、認証/認可、リスク、時間内に完成させるP0の範囲を報告してください。その後、P0の縦断フローから開発してください。
