## 2026-11-02 追加の合意事項

| ID | 決定事項 |
|---|---|
| D26 | スコアは内部で小数を保持し、UI表示時に四捨五入する。計算途中で不要な丸めを行わない。領域別スコアには教材の主領域1つを使用し、補助タグは検索に使用する。 |
| D27 | 実質改訂後、新版のクイズが未評価の場合は旧版の結果を全体平均に暫定的に含める（既定）。医療者・患者の画面では「旧版の結果」と明示し、新版は未評価として表示する。新版のクイズ完了後は新版のスコアに置き換える。安全上の理由で無効化された教材の旧版スコアは現在の理解確認スコアから除外する。集計方式を変更するシステム設定フラグを用意してよい。 |
| D28 | QRコードと同時に6桁コードを表示する。5分間有効、1回限り、患者承認必須。試行回数制限・レート制限・原子的なコード消費を実装する。患者承認前には患者の個人情報や学習履歴を表示しない。 |
| D29 | 学習履歴は患者本人が保有し、診察時の明示承認で他院の医療者とも共有できる。宿題スナップショットは処方元病院で次の診察セッションが開始された時点で一度だけ作成し、他院の診察開始では他院の宿題を自動確定しない。共有画面に他院の処方・質問を含むことを明示する。 |
| D30 | 原資料はテキスト抽出を基本とし、図表・画像・スキャンPDF等で欠落が疑われる場合は警告して手動確認を必須とする。画像解析を伴う自動処理はMVPから除外する。 |
| D31 | Claude APIは Sonnet 5.5 を基本、必要に応じて Opus 5.5。モデルは環境変数で切替。教材生成はジョブ化し進捗・成功・失敗を確認できるようにする。 |

実患者での利用承認、医療機関内の情報管理責任、外部委託契約、個人情報・要配慮情報の実運用、正式尺度としての妥当性検証、医療機関SSO・電子カルテ連携、検査OCR、診察会話音声解析、評価処方、症状ライフログ。
| D32 | 患者向け UI は C 案（静かなウェルネス）を基本とし、B 案からは学習構造（1画面1命題・進捗・明確な CTA）のみ取り入れる（C2）。医療者画面には水彩装飾を持ち込まない。 |
| D33 | 医学的図解は ChatGPT 等で 1 点ずつ制作し、医療者監修後に画像アセットとして取り込む。ラベル・注釈は画像に埋め込まず HTML/SVG で表示。`review_status = approved` かつ画像ありの図解だけを患者に配信し、未承認図解はプレースホルダーも含めて患者画面に出さない。監修プレビューは教材編集者・承認者に限定。 |
| D34 | 病期の説明は「3 つを組み合わせて決める」と断定せず、T・N・M を基本とし、分類体系によってはグレードやバイオマーカーも考慮されることを踏まえる。説明文と図解は監修前に公開しない（デモの架空教材は監修前の原稿であることを明示）。 |
