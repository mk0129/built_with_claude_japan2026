## 5. Must-cover items の実装結果

- 分類: この教材で必須（生成に指示・照合・確認の対象）／別教材で扱う（対象範囲外。照合も確認も求めない）／医療者の確認が必要（生成には含めず、承認前に確認を求める）。
- 初期分類（実 API run 2 の知見で変更、§6）: 案を選んだときは、案の根拠に含まれる章の候補を「必須」、範囲外を「別教材で扱う」、範囲外でも安全上の種別（緊急連絡・受診・禁止）は「医療者の確認が必要」。テーマ指定では安全上の種別だけ「必須」。
- 生成後の対応表: Claude の申告（画面・設問）、機械照合（引用の有無。参考）、医療者の確認（氏名・日時・メモ）。**出典があるだけでは網羅と判定しない**（`autoMatched` は表示のみ、承認条件は `confirmed`）。
- 承認前の警告: 安全上の重要事項が未確認 → 編集画面上部と承認欄に赤い警告。承認 API は `SAFETY_UNCONFIRMED`（409）で拒否し、了承（`acknowledgeSafety`）と理由を `reviewComment` と監査ログ（`material.approve_publish.safety_acknowledged`）に記録した場合のみ承認。「別教材で扱う」はこの警告の対象外。
- 実 API での通し（run 3）: 候補 8 件（emergency 2・visit 1・prohibition 2・caution 2・fact 1）。B（案 2: 副作用と連絡）では必須 3・要確認 3・別教材 2 → 必須 3 件すべて Claude の申告と機械照合が一致、承認前の未確認 5 件 → 医療者の確認後 0 件で承認。
- 工数実績: 約 6h（設計見積 12h のうち、横並び同期などを後回しにした分）。
