撮影は**再生用デモ環境**（Claude を呼ばない・課金なし）を標準とする。

### 0-1. 起動と事前準備（撮影の直前に 1 回）
```bash
cd ~/Developer/shiori-final            # feat/demo-finalization
E2E_PUBLIC_ORIGIN=http://<PC の LAN の IP>:3900 REVIEW_DIST=.next-e2e-final sh scripts/review/serve.sh 3900 5900
# 起動ログに Ready が出たら（画面を開く前に）、伊藤 涼子に「初回診断時セット」を処方した状態を作る
BASE=http://localhost:3900 node scripts/demo/prep-filming.mjs
```
- 起動のたびに新しい一時 DB。基準日は **2026年11月4日**、観察期間は **10月22日〜11月4日** に固定（`DEMO_ANCHOR`）。撮影が 11月6日・7日になっても、患者の経過グラフ・医療者の在宅経過表・Claude外来間サマリーは同じ期間を表示する。基準日の固定はこの撮影用サーバーだけで、通常の起動・本番には影響しない。
- `serve.sh` は日本時間（`TZ=Asia/Tokyo`）で起動する（架空の記録の日時と、記録済みの Claude 出力の照合を日本時間でそろえる）。
- `prep-filming.mjs` は固定データを書き込まず、本番と同じ手順（患者が 6 桁コードを発行 → 医療者 佐藤 一郎が読み取り → 患者が承認 → 医療者が「初回診断時セット」を処方 → 共有終了）を API で行う。2 回目以降は何もしない。
- 患者側の「診断時セット」は、医療者の情報処方テンプレート「初回診断時セット」の教材（乳がんの診断と病期の考え方／サブタイプと治療方針のつながり／こころのケアと相談先）が 1 回の処方にすべて含まれるときだけ表示される（処方の記録にテンプレートの ID はないため、教材の一致で判定）。
- 撮影中に佐藤 花子の記録（体調・ノート・学習）を変えない。変えると記録済みの Claude 出力は再生されず、ルールベースの要約になる。

### 0-3. 撮影の流れ（ナレーションの区切りに合わせて秒数を調整）
1. **患者ホーム**（伊藤 涼子・スマートフォン 390×844）: 次回の診察日 → 「診断時セット」のカード（さくら総合病院 佐藤 医師から届いた・教材 3 件）→「セットの内容を見る」。
2. **診断時セット**: 処方された 3 教材のカード → 「乳がんの診断と病期の考え方」→ 学ぶ（図のないページは本文だけ）。
3. **理解確認**: 「理解を確認する」→ 1 問に「わからない」→ 確定（「わからない」を記録しました）。
4. **診察で聞きたいこと**: ホームの入力欄から質問を追加。
5. **体調記録の経過**（佐藤 花子・別の架空患者）: 体調記録 →「履歴・グラフ」（手足のしびれ・14 日。記録のない日は線をつながない）。
6. **患者が QR を提示**（伊藤 涼子または佐藤 花子）: 右上「共有する」→「QRコードと6桁コードを表示する」。医療者は**ログイン済みのスマートフォンの標準カメラで QR を読み取る**（PC にカメラがなければ PC で 6 桁コード）。PC は自動で「患者の承認を待っています」へ。
7. **患者の承認**: 申請者（さくら総合病院（架空）・佐藤 医師）・共有範囲・60 分を確認 → チェック →「この医療者に共有を許可する」。
8. **Claude外来間サマリー**（佐藤 花子と共有した PC 1180×820 以上）: 冒頭の要点 3 項目（症状の経過／理解確認で「わからない」と回答した内容／患者さんが残した質問）→ 要点を押して根拠の記録を表示 →（必要なら）「要約の全項目（18項目）」。
9. **在宅経過表**: 左の「在宅経過」→ 10/22〜11/4 の経過表（— は記録なし、0 は「なし」）。
10. **情報処方**: 左の「教材ライブラリ」→「セットから選ぶ」または教材カードの「処方に追加」→「選択中 N件」→「N件の情報処方を確定」。
11. **Claude教材スタジオ**: 左の「教材スタジオ」。共有中は患者名と残り時間が上部の小さな表示にまとまる。原資料は `hormone_therapy_detailed_demo.docx`、構成案は **案 1**（再生時は案 1 に固定。案 2・3 は選べない）。7 つの手順のうち映す手順だけを撮る。
12. **共有終了**: 「共有終了」→ 医療者の画面から患者の情報が消える（以後、医療者の API は 403）。

- 患者を切り替えるときは、医療者は一度「共有終了」してから次の患者の QR／6 桁コードを読み取る（QR は 5 分・1 回限り、共有は 60 分）。
- 教材スタジオは患者との一時共有中にしか開けない（権限の設計は今回変えていない）。佐藤 花子と共有したまま撮るか、伊藤 涼子と共有し直して撮る。

## 1. 撮影用サーバー（再生用デモ環境・推奨）
```bash
E2E_CLAUDE=fake DEMO_ANCHOR=2026-11-04T09:00:00+09:00 \
  INTERVISIT_REPLAY_FILE=docs/design/phase2/step4/replay/intervisit_replay.json \
  STUDIO_REPLAY_FILE=docs/design/phase2/step5/replay/studio_replay.json \
  E2E_PORT=3700 E2E_DB_PORT=5700 NEXT_DIST_DIR=.next-demo node scripts/e2e-server.mjs
```
- API キーは空（Claude は呼ばない）。起動のたびに DB は新しくなり、前の撮影の操作は残らない。
- `DEMO_ANCHOR`: 架空の履歴を「2026-11-04 を今日」として作る。外来間サマリーの既定期間は **10月22日〜11月4日** に固定され、撮影日がずれても同じ内容になる。
- `INTERVISIT_REPLAY_FILE`: 2026-11-04 の実 API で Claude が生成し、**18 項目すべてが検証を通った**外来間要約を再生する。表示のたびに、現在の DB の記録と内容（ラベル・日時・統計値の指紋）が一致することと、全項目の根拠 ID・数値・日付・引用の検証をやり直す。1 つでも合わなければ再生せず、ルールベースの要約になる（矛盾する文は出ない）。見出しは「AI外来間サマリー（記録済みのClaude出力を再生・2026-11-04生成・現在の記録で再検証済み）」。
- `STUDIO_REPLAY_FILE`: 2026-11-04 の実 API（構成案 1 回＋本文 1 回）の出力を再生する。原資料が記録時と同じファイル（SHA-256 一致）で、**案 1** を選んだときだけ使える。教材スタジオに「撮影用デモ環境: 記録済みのClaude出力…を再生しています。今回はClaudeを呼び出していません。」と表示される。
- `NODE_ENV` / `APP_ENV` / `VERCEL_ENV` が production のときは、この 3 つの設定はすべて無視される（本番の利用者には影響しない）。
- 医療者は PC（1440×900 推奨）、患者はスマートフォン（実機、または 390×844 の表示）で別ブラウザ・別ウィンドウ。
- **医療者のスマートフォンで患者の QR を読む場合**は、起動コマンドの先頭に `E2E_PUBLIC_ORIGIN=http://<PC の LAN の IP>:3700` を付ける（IP は `ipconfig getifaddr en0` で確認。PC とスマートフォンを同じ Wi-Fi に）。患者の QR の URL がその宛先になり、スマートフォンからのログインと表示が許可される。PC の画面は従来どおり `http://localhost:3700` で開いてよい。
  - 医療者のスマートフォンでは、撮影前に `http://<PC の LAN の IP>:3700/staff/login` を開いて PC と同じ医療者（佐藤 一郎）でログインしておく（未ログインで読み取っても、ログイン後に読み取りへ戻る）。
  - 以前の手順（`BETTER_AUTH_URL` / `NEXT_PUBLIC_APP_URL` を LAN の IP にする）は、起動スクリプトが localhost で上書きしていたため効かなかった。`E2E_PUBLIC_ORIGIN` を使う。

## 3. 撮影前の準備（データ・セッションを途中で変えない）
1. 撮影の直前にサーバーを起動し直す（新しい DB）。ログに `[intervisit-ai] replay validated items=18 valid=18 rejected=0` が出ることを、リハーサルで 1 度確認する。
2. 医療者・患者のログイン（7 日間有効）は撮影開始時に済ませる。共有は承認から **60 分**で切れる（画面右上の残り時間）。60 分を超えそうなら「共有を延長」→ 患者が承認。患者の QR と 6 桁コードは **5 分**で失効し、1 回限り（自動では差し替わらない。切れたら患者が表示し直す）。撮影では表示したらすぐ読み取る。
3. 佐藤 花子のデータを変えない: 体調記録・ノート・学習はすべて伊藤 涼子で行う。佐藤 花子の記録を追加・変更すると、再生の条件（記録時と同じ記録）が崩れ、AI 要約はルールベースに切り替わる（誤った文は出ない）。
4. 教材スタジオでは原資料 `tests/fixtures/sources/hormone_therapy_detailed_demo.docx`（デモ用に独自作成した架空原稿）を使い、**案 1「ホルモン療法の目的と続け方」**を選ぶ。案 2・3 は記録がないため下書きは作られない。
5. 次回診察日は**どの患者にも登録されていない**（架空の日付は入れていない）。患者ホームの最上部は「次回の診察日は未登録です」から始まる。登録して見せる場合は伊藤 涼子で行う（佐藤 花子のデータは変えない）。
6. 通知・ほかのアプリを閉じ、ブラウザの拡大率 100%、開発用画面（`/d/dev`）は開かない。

### 5-A. 正式な方式: 患者が QR コードを提示し、ログイン済みの医療者が読み取る（撮影はこの方式）
1. 医療者（佐藤 一郎）: PC で `/staff` にログイン済み。医療者のスマートフォンも同じアカウントでログインしておく（§1）。
2. 患者（スマートフォン）: 画面右上の「共有する」→「QRコードと6桁コードを表示する」。1 回の発行で QR と 6 桁コードが同時に出る（同じ申請・5 分・1 回限り）。
3. 医療者: スマートフォンの**標準カメラ**で患者の QR を読み取り、表示されたリンクを開く → 申請が送られ、スマートフォンは「患者の承認を待っています」。**同じアカウントでログインしている PC の画面も自動で「患者の承認を待っています」に切り替わる。** shiori の中にカメラ起動のボタンはない。
4. 患者: 画面に医療機関・医療者・共有する内容・有効期間（承認した時点から 60 分）が出る →「一時共有の内容を確認しました」にチェック →「この医療者に共有を許可する」（「共有しない」も選べる）。
5. 医療者の PC の画面が自動で診察サマリーに切り替わる（スマートフォンでも同じセッションが開く）。
6. 終了: 患者の「一時共有を終了する」、または医療者の「共有を終了」。60 分が過ぎたときも同じ。終了後、医療者は患者の情報を取得できない（403）。延長は医療者の「共有を延長」→ 患者の再承認。

### 5-B. PC にカメラがない場合: 患者の 6 桁コードを医療者が PC で入力する
1. 患者: 5-A の 2 と同じ（QR と同時に出る 6 桁コードを使う）。
2. 医療者（PC）:「患者のQRを読み取る／6桁コードを入力」→ 患者のコードを入力 →「患者へ承認を依頼する」→「患者の承認を待っています」。**入力しただけでは共有されない。**
3. 患者: 5-A の 4 と同じ。医療者の画面に診察サマリーが出る。
- 片方（QR かコード）で読み取られると、もう片方は使えない。取り消しは患者の「QRとコードを取り消す」、承認待ちの医療者の「申請を取り消す」（患者の画面から申請が消え、承認できなくなる）。使用済み・取り消し済み・期限切れのコードは使えない。入力の失敗が 10 分で 5 回続くと、しばらく入力できない。
- 撮影の画面に QR とコードが映るが、5 分で失効し 1 回限り（撮影後に使われても患者の承認がなければ共有されない）。編集で隠す必要はないが、公開前に気になる場合はぼかす。
- PC だけで撮る場合（スマートフォンを使わない）は 5-B で撮る。

- 互換: 医療者が QR を表示して患者が読み取る方式（`/home?view=share&connect=…`）のサーバー処理は残しているが、通常の画面からは発行しない。撮影には使わない。
