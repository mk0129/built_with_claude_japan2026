# デモ撮影の手順（Screen Studio）

すべて架空のデータ（@example.com のアカウント、架空の病院・患者・教材）。実患者情報は使わない。

## 1. 撮影用サーバー（新しい一時 DB）
```bash
# Claude を呼ばない撮影（擬似生成。教材スタジオの生成結果は「【擬似生成】」の文になる）
E2E_PORT=3700 E2E_DB_PORT=5700 NEXT_DIST_DIR=.next-demo node scripts/e2e-server.mjs

# 実 Claude で撮影（課金あり・事前の承認が必要）。呼び出し回数を必ず制限する
E2E_CLAUDE=real CLAUDE_MAX_RETRIES=0 CLAUDE_MAX_CALLS=<承認された回数> INTERVISIT_AI_MAX_CALLS=1 AI_JOB_MAX_ATTEMPTS=1 \
  E2E_PORT=3700 E2E_DB_PORT=5700 NEXT_DIST_DIR=.next-demo node scripts/e2e-server.mjs
```
- 起動のたびに DB は新しくなる（前の撮影の操作は残らない）。
- 医療者は PC（1440×900 推奨。Figma の 1180 幅が中央に表示）、患者はスマートフォン表示（390×844）で別ブラウザ・別ウィンドウ。
- iPhone で QR を読む場合は `BETTER_AUTH_URL` / `NEXT_PUBLIC_APP_URL` を PC の LAN の IP（例 `http://192.168.x.x:3700`）にして起動する。

## 2. アカウント
| 役割 | 表示名 | 用途 |
|---|---|---|
| 医療者（診療・教材編集・教材承認） | 佐藤 一郎 | 教材の作成・承認（**架空の承認者。本番の医学的監修ではない**）・処方・共有 |
| 患者 | 伊藤 涼子 | 履歴なし。教材の学習・記録から始める |
| 患者 | 佐藤 花子 | 2 週間の体調記録・学習・質問の履歴あり（在宅経過表・外来間サマリーの見せ場） |

## 3. シーン（推奨順）
| # | シーン | 操作 |
|---|---|---|
| 1 | Claude による教材生成と医学的承認 | 医療者でログイン →「患者との接続を開始」→ 患者（伊藤）が QR を読んで許可 → 教材スタジオ → 原資料 `tests/fixtures/sources/hormone_therapy_detailed_demo.docx`（デモ用の架空原稿）・作成元・許諾の根拠・2 つの確認 → 構成案 → Must-cover を原文と照合 → 編集 → プレビュー → 4 項目を確認して承認・公開 |
| 2 | 医療者による情報処方 | 教材ライブラリ → 新しい教材を「処方に追加」→ 確定 →「診察を終えて共有終了」 |
| 3 | 患者の学習と「わからない」 | 患者のホーム → 新しい教材 → 学習 → 理解確認で「わからない」→ 解説 |
| 4 | 体調記録・診察ノート | 体調記録（体温・手足のしびれ）→ 診察ノートに質問 |
| 5 | QR による一時共有 | 医療者が QR を表示 → 患者が申請者・有効期間を確認して「この医療者に共有を許可する」 |
| 6 | 在宅経過表 | 「在宅経過」→ 経過表（未記録は —、同じ日の 2 回は ×2）→「バイタル統合」で凡例の切替とカーソル表示 |
| 7 | AI 外来間サマリーと根拠 | 「診察」→「直近14日間の経過」→ 文を押して根拠の記録 |
| 8 | 追加の情報処方 | 「わからない」の詳細 →「再処方候補へ」→ 関連教材を追加 → 確定 |
| 9 | 追加入力なしで終了 | 「診察を終えて共有終了」→ 医療者の画面から患者情報が消える |
- 在宅経過表・外来間サマリーを見せる場面（6・7）は、記録の多い**佐藤 花子**で共有すると分かりやすい（伊藤 涼子は当日の記録だけになる）。

## 4. 注意
- 開発用の画面（`/d/dev`）は撮影しない。本番の画面に「架空データ」「未接続」の表示は出ない（教材スタジオの「Step 1〜7」は画面の構成要素）。
- AI 外来間サマリーは、Claude の出力がサーバーの検証を通らないとルールベースの要約に切り替わり、見出しにその旨が出る（実 API の検証結果: `docs/design/phase2/step4/real_screen/final/README.md`）。
- 擬似生成での撮影では、見出しが「AI外来間サマリー（開発用の擬似生成・Claudeではありません）」になる。
