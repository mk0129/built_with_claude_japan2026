# デモ撮影の手順（Screen Studio）

すべて架空のデータ（@example.com のアカウント、架空の病院・患者・教材）。実患者情報・施設資料は使わない。
撮影は**再生用デモ環境**（Claude を呼ばない・課金なし）を標準とする。

## 1. 撮影用サーバー（再生用デモ環境・推奨）
```bash
E2E_CLAUDE=fake DEMO_ANCHOR=2026-11-04T09:00:00+09:00 \
  INTERVISIT_REPLAY_FILE=docs/design/phase2/step4/replay/intervisit_replay.json \
  STUDIO_REPLAY_FILE=docs/design/phase2/step5/replay/studio_replay.json \
  E2E_PORT=3700 E2E_DB_PORT=5700 NEXT_DIST_DIR=.next-demo node scripts/e2e-server.mjs
```
- API キーは空（Claude は呼ばない）。起動のたびに DB は新しくなり、前の撮影の操作は残らない。
- `DEMO_ANCHOR`: 架空の履歴を「2026-11-04 を今日」として作る。外来間サマリーの既定期間は **10月22日〜11月4日** に固定され、撮影日がずれても同じ内容になる。
- `INTERVISIT_REPLAY_FILE`: 2026-11-04 の実 API で Claude が生成し、**18 項目すべてが検証を通った**外来間要約を再生する。表示のたびに、現在の DB の記録と内容（ラベル・日時・統計値の指紋）が一致することと、全項目の根拠 ID・数値・日付・引用の検証をやり直す。1 つでも合わなければ再生せず、ルールベースの要約になる（矛盾する文は出ない）。見出しは「AI外来間サマリー（記録済みのClaude出力を再生・2026-11-04生成・現在の記録で再検証済み）」。
- `STUDIO_REPLAY_FILE`: 2026-11-04 の実 API（構成案 1 回＋本文 1 回）の出力を再生する。原資料が記録時と同じファイル（SHA-256 一致）で、**案 1** を選んだときだけ使える。教材スタジオに「撮影用デモ環境: 記録済みのClaude出力…を再生しています。今回はClaudeを呼び出していません。」と表示される。
- `NODE_ENV` / `APP_ENV` / `VERCEL_ENV` が production のときは、この 3 つの設定はすべて無視される（本番の利用者には影響しない）。
- 医療者は PC（1440×900 推奨）、患者はスマートフォン表示（390×844）で別ブラウザ・別ウィンドウ。iPhone で QR を読む場合は `BETTER_AUTH_URL` / `NEXT_PUBLIC_APP_URL` を PC の LAN の IP（例 `http://192.168.x.x:3700`）にして起動する。

- `feat/patient-ui-logo-a` の画面（ロゴ A・新しい入口とログイン・患者ホームの次回診察日・患者発行 QR）を確認する隔離環境: `sh scripts/review/serve.sh`（ポート 3800・DB 5800・新しい一時 DB。上と同じ再生設定）。次回診察日の表（`patient_next_visits`）は起動時のマイグレーションで作られる。安定版の撮影環境（3300・3400 など）とは別のポート・DB・ビルドフォルダを使う。

参考: 実 Claude で撮影する場合（課金あり・**事前の承認が必要**）。呼び出し回数を必ず制限する
```bash
E2E_CLAUDE=real CLAUDE_MAX_RETRIES=0 CLAUDE_MAX_CALLS=<承認された回数> INTERVISIT_AI_MAX_CALLS=1 AI_JOB_MAX_ATTEMPTS=1 \
  E2E_PORT=3700 E2E_DB_PORT=5700 NEXT_DIST_DIR=.next-demo node scripts/e2e-server.mjs
```

## 2. アカウント（固定）
| 役割 | 表示名 | 用途 |
|---|---|---|
| 医療者（診療・教材編集・教材承認） | 佐藤 一郎 | 教材の作成・承認（**架空のデモ承認者。本番の医学的監修ではない**）・処方・共有 |
| 患者 | 伊藤 涼子 | 履歴なし。教材の学習・「わからない」・体調記録・診察ノート（シーン 2〜5） |
| 患者 | 佐藤 花子 | 2 週間の体調記録・学習・質問の履歴あり。在宅経過表・AI 外来間サマリー（シーン 6〜8）。**撮影中に記録を追加しない** |

## 3. 撮影前の準備（データ・セッションを途中で変えない）
1. 撮影の直前にサーバーを起動し直す（新しい DB）。ログに `[intervisit-ai] replay validated items=18 valid=18 rejected=0` が出ることを、リハーサルで 1 度確認する。
2. 医療者・患者のログイン（7 日間有効）は撮影開始時に済ませる。共有は承認から **60 分**で切れる（画面右上の残り時間）。60 分を超えそうなら「共有を延長」→ 患者が承認。QR・接続コードは **5 分**で失効する（画面の QR は自動で新しいものに差し替わる）。撮影では QR を表示したらすぐ読み取る。
3. 佐藤 花子のデータを変えない: 体調記録・ノート・学習はすべて伊藤 涼子で行う。佐藤 花子の記録を追加・変更すると、再生の条件（記録時と同じ記録）が崩れ、AI 要約はルールベースに切り替わる（誤った文は出ない）。
4. 教材スタジオでは原資料 `tests/fixtures/sources/hormone_therapy_detailed_demo.docx`（デモ用に独自作成した架空原稿）を使い、**案 1「ホルモン療法の目的と続け方」**を選ぶ。案 2・3 は記録がないため下書きは作られない。
5. 次回診察日は**どの患者にも登録されていない**（架空の日付は入れていない）。患者ホームの最上部は「次回の診察日は未登録です」から始まる。登録して見せる場合は伊藤 涼子で行う（佐藤 花子のデータは変えない）。
6. 通知・ほかのアプリを閉じ、ブラウザの拡大率 100%、開発用画面（`/d/dev`）は開かない。

## 4. シーン（推奨順）
| # | シーン | 操作 |
|---|---|---|
| 0 | 入口とログイン | `/` の入口（ロゴ A）→「患者の方はこちら」→ ログイン画面の「デモ用アカウント」から伊藤 涼子。医療者は入口の「医療者の方はこちら」→ 佐藤 一郎 |
| 1 | Claude による教材生成と承認 | 佐藤 一郎でログイン →「患者との接続を開始」→ 伊藤 涼子が QR を読んで許可 → 教材スタジオ → 原資料・作成元・許諾の根拠・2 つの確認 → 構成案（案 1）→ Must-cover を原文と照合 → 編集 → プレビュー → 4 項目を確認して承認・公開 |
| 2 | 情報処方 | 教材ライブラリ → 新しい教材を「処方に追加」→ 確定 →「診察を終えて共有終了」 |
| 3 | 患者ホームと学習・「わからない」 | 伊藤 涼子のホーム。最上部の「次回診察日を登録」→ 日付を入れて「保存する」→「次の診察まで あと N 日」。その下の「続きから学ぶ／教材を確認する」→ 学習 → 理解確認で「わからない」→ 解説 |
| 4 | 体調記録・診察ノート | 伊藤 涼子のホームの「診察で聞きたいこと」に質問を入力して「追加」（下に表示され、診察ノートにも入る）→「今日の体調を記録」で体温・手足のしびれ |
| 5 | QR による一時共有（2 方式。下の 5-A・5-B） | どちらも患者が申請者・医療機関・有効期間（承認から 60 分）を確認して「この医療者に共有を許可する」まで共有されない |
| 6 | 在宅経過表 | 「在宅経過」→ 経過表 →「バイタル統合」 |
| 7 | AI 外来間サマリーと根拠 | 「診察」→「直近14日間の経過」→ 文を押して根拠の記録（例: 手足のしびれ、「わからない」、診察ノートの質問） |
| 8 | 追加の情報処方 | 「わからない」の詳細 →「再処方候補へ」→ 関連教材を追加 → 確定 |
| 9 | 終了 | 「診察を終えて共有終了」→ 医療者の画面から患者情報が消える |

### 5-A. 医療者が QR を表示して、患者が読み取る（従来の方式）
1. 医療者（佐藤 一郎）:「患者との接続を開始」→ QR コードのタブ（5 分で失効し、自動で新しい QR に差し替わる）。
2. 患者（佐藤 花子のスマートフォン）: カメラで QR を読み取る（ログインしていなければ、ログイン後に同じ申請へ戻る）。
3. 患者: 申請者を確認 →「一時共有の内容を確認しました」にチェック →「この医療者に共有を許可する」。医療者の画面に診察サマリーが出る。

### 5-B. 患者が自分の QR と 6 桁コードを表示して、医療者が読み取る（新しい方式）
1. 患者: 画面右上の「共有する」→「QRコードと6桁コードを表示する」。1 回の発行で QR と 6 桁コードが同時に出る（同じ申請・5 分・1 回限り）。
2. 医療者は次のどちらか。
   - QR: 医療者のタブレット・スマートフォンの**標準カメラ**で読み取ると `/c` が開く（未ログインなら医療者ログイン後に戻る）→「患者の承認を待っています」。アプリ内のカメラでの読み取りはない。実機で読む場合は `BETTER_AUTH_URL` / `NEXT_PUBLIC_APP_URL` を PC の LAN の IP にして起動し、その端末で医療者としてログインしておく。
   - 6 桁コード（PC で撮影するときはこちら）:「患者との接続を開始」→「6桁コード」→ 患者の画面のコードを入力 →「患者へ承認を依頼する」→ 承認待ち。
3. 患者: 画面に読み取った医療者・医療機関・有効期間が出る → チェック →「この医療者に共有を許可する」（「共有しない」も選べる）。医療者の画面に診察サマリーが出る。
4. 片方（QR かコード）で読み取られると、もう片方は使えない。取り消すときは「QRとコードを取り消す」。
- 注意: 撮影の画面に QR とコードが映るが、どちらも 5 分で失効し 1 回限り（撮影後に使われても患者の承認がなければ共有されない）。編集で隠す必要はないが、公開前に気になる場合はぼかす。
