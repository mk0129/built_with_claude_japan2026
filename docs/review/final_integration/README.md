## 2. QR 共有の正式な操作

1. 医療者は自分のアカウントで `/staff` にログイン済み（読み取りに使うスマートフォンも同じアカウントでログイン）。
2. 患者が共有画面（右上「共有する」）で「QRコードと6桁コードを表示する」→ 1 回の発行で QR と 6 桁コードを同時に表示（同じグラント・5 分・1 回限り）。
3. 医療者が読み取る:
   - **QR**: スマートフォン・タブレットの標準カメラで読み取る → `/c`（未ログインなら医療者ログイン後に戻る）→ 読み取り要求 → 承認待ち。**同じアカウントの PC の画面も自動で承認待ちに切り替わる。**
   - **6 桁コード**（PC にカメラがない場合）: 「患者のQRを読み取る／6桁コードを入力」→ 入力 →「患者へ承認を依頼する」→ 承認待ち。
4. 患者の画面に医療機関・医療者・共有範囲・時間（承認した時点から 60 分）が出る → 確認のチェック →「この医療者に共有を許可する」（「共有しない」も可）。
5. 患者の承認後、医療者の PC が自動で診察サマリーへ（スマートフォンでも同じセッション）。
6. 60 分経過・患者または医療者の終了で、医療者の API は 403。延長は医療者の申請 → 患者の再承認。

画面の整理:
- 患者: 共有画面に 3 段階の手順と「QRコードと6桁コードを表示する」。カメラ起動のボタンは置かない。
- 医療者: 通常画面のボタンを「患者のQRを読み取る／6桁コードを入力」にし、QR の読み取り方（標準カメラ・PC も自動で切り替わる）と 6 桁コードの入力を同じ画面に表示。**医療者が QR を発行する画面は通常 UI から外した**（`/api/v1/connect` などのサーバー処理と、患者側の確認画面 `/home?view=share&connect=…` は互換として残す）。開発用 `/d/dev` の Figma プロトタイプはそのまま。
- 承認待ちで医療者が「申請を取り消す」と、そのグラントは無効になり、患者の画面から申請が消える（患者には「医療者が申請を取り消しました」）。

## 3. サーバーの変更（理由と範囲）

CLAUDE.md の「QR 連携・60 分のアクセス制御は変更しない」に関わるため、変更点を明記する。既存の処理（発行・読み取り・承認・期限・延長・終了・試行回数の制限・監査）は変更していない。追加は 2 つだけ。

| 追加 | 理由 | 安全性 |
|---|---|---|
| `GET /api/v1/staff/live`（`getLiveStateForStaff`） | 医療者がスマートフォンで QR を読み取ったとき、同じアカウントの PC の画面を承認待ち → 診察サマリーへ切り替えるため（ご指示の「必要なら安全に同期する」） | 医療者本人が読み取り要求した承認待ちグラントの ID と、本人の有効な診察セッションの ID だけを返す。患者の氏名・記録は返さない。セッションの中身は従来どおり担当医療者・期限内・未終了のときだけ読める |
| `POST /api/v1/qr/claim/:id/cancel`（`cancelClaimByStaff`） | 同期を入れると、取り消した承認待ちが PC で再び表示されてしまうため。承認待ちの「申請を取り消す」をサーバーでも確定させる | 読み取り要求した本人の、承認前（pending）のグラントだけ。取り消すと患者は承認できない（409）。監査 `qr.claim_cancel`。試行回数の制限の数え方は変えていない |
