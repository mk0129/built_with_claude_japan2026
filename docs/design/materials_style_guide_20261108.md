# 教材の規約（文体・画面・確認問題）— 2026-11-08

shiori の患者向け教材を書くとき・直すとき・Claude に作らせるときの共通ルール。
シード教材（`src/server/db/seed-content*.ts`）と、教材スタジオで Claude が作る下書きの両方に当てる。
機械チェックは `src/lib/material-quality.ts`（規約の §6）。医学的な正しさは機械では判定せず、医療者の監修で見る。

## 1. 教材の単位
- 1 教材 = 1 つのテーマ、3〜7 画面（Claude の下書きは 3〜5 画面）、確認問題 2〜5 問。
- 学習目標は 1〜3 個、「〜を知る」の形。各目標に対応する画面と設問が 1 つ以上ある。
- 読者は成人の患者。治療でつらい日にスマートフォンで読む前提で、1 画面は 20 秒で読み切れる量にする。

## 2. 画面（スライド）
| 要素 | 役割 | 目安 |
| --- | --- | --- |
| 見出し（title） | 何の話か | 15 文字以内 |
| 要点（proposition） | この画面の結論を 1 文で。読者が覚えて帰る文 | 45 文字以内。です・ます調 |
| 本文（body） | 要点の理由・具体例。要点を繰り返さない | 2〜3 文、40〜120 文字。1 文 60 文字以内 |
| 補足（detail） | 例外、時期の目安、準備、関連する相談先。折りたたまれるので本文に入らない細部を置く | 170 文字以内。不要なら空 |

- **1 画面 1 主題**。原資料の別の章の内容を同じ画面に混ぜない。
- **行動につながる画面を 1 つ以上**置く（連絡・受診・相談・伝える・聞く・問い合わせる・申請する・記録する）。テーマの範囲に「病院へ連絡する目安」があれば、まとめの直前の画面にまとめる。
- **まとめ画面**は最後に 1 つ。要点 = 教材全体の結論 1 文、本文 = 要点の再掲 2〜3 点 ＋ 「この内容は一般的な説明です。あなたの治療については、担当医の説明が優先されます。気になることは次の診察で聞いてください。」（150 文字以内）。
- 数値は、原資料や施設の指示が前提になるものは「病院から伝えられた目安」と書き、固定値を一般化しない。

## 3. 文体
- やさしい日本語。1 文 1 内容。専門用語には最初に言い換えを添える（例: 病期（ステージ）、好中球（感染と戦う白血球））。
- です・ます調。命令形にしない（「〜しましょう」「〜してください」）。子ども扱い・過度な励ましはしない。
- 数字は半角。全角数字・全角英字は使わない。
- 書かないこと: 個別の診断、緊急度の判定、予後の数値、原資料にない薬剤名・頻度・用量。「必ず」「絶対」「二度と」のような断定。
- 用語の統一: 担当医（主治医は制度名「主治医意見書」のときだけ）、医療者、がん相談支援センター、体調記録、聞きたいこと、理解確認。
- 内部コード（drug_therapy、clinician など）を本文に出さない。

## 4. 確認問題
目的は「読者がどこでつまずいたかを医療者と共有する」こと。試験ではないので、知識の再生より「迷う場面で正しく動けるか」を見る。
- 2〜5 問、各問は 1 つの画面に対応（relatedSlide）。選択肢はちょうど 3 つ。「わからない」はアプリが足す。
- **状況判断型を 1 問以上**: 「〜のとき、どうしますか」のように、人物と場面を 1 文で置いてから問う。
- **残りも場面を置く**: 「〜について正しいものはどれですか」だけで構成しない。
- **誤答は、患者が実際に取りがちな行動・誤解から作る**（例: 症状がなければやめてよい、市販薬で様子を見る、期間は全員同じ、家族には黙っておく）。「何もしない」「気にしない」「血液型」のような明らかな誤りは置かない。
- **選択肢は同じ文体・同じくらいの長さ**。最長が最短の 1.5 倍を超えないようにし、正答だけが詳しく・長く・限定語つきにならないようにする（長さで正答がわかる問題は不合格）。
- **正答の位置を分散**する。3 問なら 1・2・3 番目を 1 回ずつ。
- **解説**は 20〜150 文字で、正答の理由 → 迷いやすい誤答がなぜ不適切か → （Claude の下書きでは）原資料の根拠、の順。不適切な行動を含む誤答があるときは、正しい対応を明示する。
- 誤答の文章にも、原資料にない医学情報を入れない。

## 5. 監修で見ること（機械では判定しない）
- 原資料との一致（引用の存在だけでなく意味が変わっていないか）、施設ごとの数値、受診・連絡の目安の妥当性。
- 患者の誤解を招く省略がないか（GEN-01: 受診・連絡・禁止の行動が落ちていないか）。
- 誤答が「医学的に危険な行動」を含む場合、解説で正しい対応が示されているか。

## 6. 機械チェック（`src/lib/material-quality.ts`）
| コード | 内容 | しきい値 |
| --- | --- | --- |
| SLIDE_COUNT / Q_COUNT | 画面数・問題数 | 3〜7 画面、2〜5 問 |
| TITLE_LONG / PROPOSITION_LONG / Q_STEM_LONG | 長さ | 32 / 45 / 90 文字 |
| BODY_SHORT / BODY_LONG / SENTENCE_LONG / BODY_MANY_SENTENCES | 本文の量 | 40〜120 文字（まとめは 150）、1 文 60 文字、4 文以内（まとめは定型 3 文を加えた 7 文） |
| BODY_REPEATS_PROPOSITION | 本文が要点をそのまま含む | — |
| DETAIL_LONG | 補足の長さ | 170 文字 |
| CLOSING_MISSING | まとめに「担当医の説明が優先」がない | — |
| ACTION_MISSING | 行動につながる文が本文にない | — |
| INTERNAL_CODE（error） | 内部コードが本文にある | — |
| Q_OPTIONS / Q_UNKNOWN_OPTION / Q_CORRECT_INDEX / Q_DUPLICATE_OPTION（error） | 選択肢の形式 | 3 つ、重複なし |
| Q_OPTION_LENGTH | 選択肢の長さの差 | 最長 ÷ 最短 ≤ 1.6、各 60 文字以内 |
| Q_CORRECT_LONGEST | 正答だけが長い | 正答 > 2 番目 × 1.3 |
| Q_OBVIOUS_DISTRACTOR | 明らかな誤答 | 語のリスト |
| Q_NO_SITUATIONAL / Q_ALL_GENERIC | 設問の型 | 状況判断型 ≥ 1、一般的な問いだけは不可 |
| Q_EXPLANATION_LENGTH | 解説の長さ | 20〜150 文字 |
| Q_POSITION_SAME / Q_POSITION_SKEW | 正答の位置 | 全問同じ位置は不可、4 問以上で 1 か所に n−1 問は偏り |

使い方:
```bash
npx tsx scripts/review/materials-lint.mts            # シード教材の一覧と集計（error で exit 1）
npx tsx scripts/review/materials-lint.mts --detail   # 指摘を 1 件ずつ
```
Claude の下書きは `validateMaterial` が同じチェックを「品質:」付きの警告として返し、下書きの `validationWarnings` に残る。
