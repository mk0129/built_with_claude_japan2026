## 3. セットの判定方法と限界（DB マイグレーションなし）

処方の記録（`prescription_sets` は診察ごと、`prescription_items` は教材ごと）には、どのテンプレート（セット）から選んだかを保存していない。そのため次の方法で判定している。

- 判定: 1 回の処方（1 診察）に、テンプレートの教材が**すべて**含まれていれば、そのテンプレートのセットとして表示する（`listHomeworkForPatient` の `templates`、`getPatientLibrary` の `latestSetTemplates`・`prescribedSets`）。表示用の読み取りだけで、処方の処理には使わない。
- 患者ホームのセットカードは**最新の処方**だけを見る。テーマの画面（仕事とお金のこと）は、これまでのすべての処方から探す（新しい順の最初）。
- 限界:
  1. 医療者がセットを使わず 4 件を個別に選んでも、同じ処方に 4 件そろえば「セット」と表示される（個別処方とセット処方を区別できない）。
  2. 4 件を別々の診察に分けて処方すると、セットとして表示されない。
  3. テンプレートの中身を後で変えると、過去の処方も変更後の定義で判定される。
  4. 同じ処方が複数のテンプレートを満たすときは、両方とも該当する。
- 誤認を避けるための表示: 送り元と日付は実際の処方の記録から表示し、「セットを使って処方した」とは書かない（「情報処方セット」のラベルと「〇〇から届きました」）。
- 正式に区別するには、処方の記録にテンプレートの ID を保存する変更（DB マイグレーション・処方の処理の変更）が必要。今回は行っていない（要承認）。
