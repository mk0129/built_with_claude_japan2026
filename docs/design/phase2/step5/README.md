# Phase 2 Step 5 — 教材スタジオの実データ接続とデモの通し（2026-11-04）

## 1. 教材スタジオ（Figma の 7 工程 → 既存 API）
| 工程 | 実際の処理（既存のバックエンドを再利用） |
|---|---|
| 1 原資料 | ファイルを選択（PDF / Word / PowerPoint / TXT、15MB まで）→ 非公開ストレージに保存しテキスト抽出（`POST /api/v1/studio/sources`）。資料名・作成元（許諾元）・**利用許諾の根拠**・利用条件（AI 処理・改変・公開・施設外共有）・**患者個人情報を含まないことの確認**を記録。AI 処理不可・個人情報の確認なしでは先へ進めない（サーバーでも送信前に確認） |
| 2 作成方針 | Claude に構成案を依頼（`outline` ジョブ）／テーマ・対象者・学習目標を指定して下書き（`freeform` ジョブ） |
| 3 構成案 | Claude の構成案（対象者・学習目標・画面構成・出典）を比較して医療者が選ぶ |
| 4 Must-cover | Claude が原資料から挙げた必須事項の候補を、医療者が原文と照合・修正して確認。確認した項目は「この教材で必須」、外した項目は「医療者の確認が必要」として下書きに渡し、確認した医療者と日時を記録 |
| 5 教材編集 | 下書きの見出し・要点・本文・確認問題（3 択＋わからない・正答・解説）を編集し、入力欄を離れると自動保存（`PUT /api/v1/studio/materials/:versionId`）。原資料の根拠（引用）を表示。医学図解は監修済みの画像だけを表示（ここでは未設定） |
| 6 プレビュー | 下書きを患者向けと同じ構成で表示（学習記録は作らない）→ 承認依頼（`submit`） |
| 7 承認・公開 | 4 項目の最終確認 → 医学的承認・公開（`approve`。承認権限・許諾・安全上の重要事項をサーバーで検証）／差し戻し（`return`）／公開停止（`retire`）。**デモの承認者は架空で、本番の医学的監修ではない**と画面に表示 |
- 公開した教材は施設内教材として教材ライブラリに追加され、情報処方で患者へ配信できる（承認前の教材は処方候補に出ない — 既存）。
- 教材スタジオは教材編集・承認の権限を持つ医療者だけが使える（権限がなければ画面で案内。権限はサーバーで検証）。
- Figma の架空データ表示（開発用 /d/dev）は変更なし（画素比較で C14〜C20 は差分 0）。
- 医療者画面の上部「架空データ」表示は、すべて実データになったため出さない。

## 2. 外来間要約の検証の修正（Step 4 の小修正）
- 件数は根拠から計算した値と完全一致（理解確認の結果別・種類別・記録日・同日の件数）。「3問中2問は正答」の数え違いも不採用。
- 「患者からの質問」の節では質問の原文全体を「」で引用することを必須。言い換えは「時系列の経過」の節だけで、「」に入れた言い換えは引用照合で不採用。禁止語の条件は緩めていない。
- 同時の要求を 1 回の生成にまとめる（画面の二重読み込みで Claude を二重に呼ばない）。呼び出し上限 `INTERVISIT_AI_MAX_CALLS`。
- 実画面検証: `docs/design/phase2/step4/real_screen/`（実 API 1 回。結果を画面に出せず、原因を修正。再実行は承認待ち）。
