## 1. DB・API・画面の変更
- **DB**: `learning_progress.started_at`（学習開始日時。`0011`。既存行は不明のため NULL のまま、既定値は新しい行だけ）。デモ用に架空の患者A の体調記録 8 件（未記録日・同じ日の 2 回・しびれの変化・途中から回答のない症状）と診察ノート 1 件、E2E 用の架空の患者C（履歴なし）を追加。
- **API（すべて有効な診察セッションが必要。なければ 403。監査記録あり）**

- **サービス**: `intervisit.ts`（統合）、`intervisit-rules.ts`（ルールベース・根拠索引）、`intervisit-ai.ts`（Claude・検証・キャッシュ）、`intervisit-format.ts`（日本時間の日付）。

## 2. 観察期間（医療安全上の判断）
- 前回外来日は DB にない。**前回の共有日を前回外来日として扱わない**。
- 既定は「直近14日間」。医療者が「期間を確認・変更」で開始日・終了日を選ぶ（92 日まで、未来不可）。見出しは「直近14日間の経過」「指定期間の経過」。過去の共有日は「前回共有日 M/D（前回外来日ではありません）」と明記。
- 在宅経過表は 7・14・28 日・指定期間。Figma の「前回外来から」は本番では出さない。
- 将来の拡張案（今回は未実装・要判断）: `confirmed_visits`（外来日・医療機関・登録者・確認方法）を医療者が登録し、確認済みの外来日がある場合だけ「前回外来からの経過」を既定にする。誰が登録・確定できるか（医師・看護師・事務、電子カルテ連携）は運用の判断が必要。

## 3. 構造化データ（サーバー側）
- A バイタル: 測定日時・値・件数・記録日数・最小・最大（根拠 ID つき）・欠測日。
- B 症状: 症状名（独自の症状名を含む）・程度・日時、期間内に新たに記録された症状（期間前に記録があり、その中にない場合だけ）、程度の変化、途中から回答がない症状（欠測。症状がなくなったとは扱わない）。
- C 学習: 教材名・版・処方日時・学習開始・完了（理解確認まで）・状態・回答（誤答・「わからない」）。
- D 質問: 診察ノート・学習後の質問、本文、作成日時、関連教材。
- すべての出来事に安定した ID（`hr:`記録 / `hs:`記録:症状 / `rx:`処方 / `lp:`学習開始 / `at:`完了 / `qa:`回答 / `vn:`診察ノート / `fb:`学習後の質問）と元の表・行。日付は Asia/Tokyo で区切り、同じ日は時刻順（同時刻は ID 順）。集計値も `stat:` ID で参照できる。

## 4. Claude の要約と検証
- 送るのは構造化データ（出来事 ID・日時・値・質問の原文）だけ。氏名・メールは送らない。**外部 AI へ送るのは架空のデモ患者（@example.com）だけ**（それ以外はルールベース）。API キーはサーバーのみ。
- 出力は「節・文・根拠 ID」の構造化項目（体調の変化／学習の状況／患者からの質問／時系列の経過）。
- サーバー側の検証（項目ごと）: 根拠 ID が存在する／数値は根拠の値（「n/4」の分子を含む）か根拠の件数以下／日付（M月D日）・時刻は根拠の日時／「」の引用は根拠の原文・教材名・設問どおり／禁止語（改善・悪化・正常・異常・Grade・診断・可能性・原因・副作用による・推奨・減量・理解力・症状なし など。「」内は対象外）。
- 代替表示: 禁止語があれば要約全体を非表示、検証できない項目が 1/3 を超える・項目が 0・質問があるのに質問の項目がない・生成エラー → ルールベース（理由に患者情報を含めない）。AI とルールベースは見出しで区別し、医療者はいつでもルールベースに切り替えられる。
- 同じ共有・期間・データならサーバーで再利用（元データが変わればハッシュが変わり再生成）。共有終了で破棄。

## 5. 視覚的な変更（Figma との差分）
| 箇所 | 変更 | 理由 |
|---|---|---|
| 統合グラフ | 本番では、その指標を測らなかった日をはさむ 2 点を線で結ばない | 欠測期間を連続測定のように描かない（Figma は全点を結ぶ） |
| 経過表のセル | 同じ日の複数回は最後の値＋「×n」、詳細にその日の全測定（時刻・値・部位・回数・支障） | 同じ日の記録を失わない（Figma は 1 日 1 記録） |
| 期間 | 7・14・28 日・指定期間（日付入力）。終了日は今日 | 前回外来日がない。Figma の固定日付を使わない |
| 日付の列 | 端末の現地日付で作る | Figma の `dateRange` は UTC に変換するため日本時間で 1 日ずれる（本番だけ置き換え） |
| 経過欄の見出し | 「直近14日間の経過」「前回共有日（前回外来日ではありません）」 | 前回外来日を推測しない |
| 要約本文 | 文ごとに押せる（点線の下線）。押すと根拠の記録を表示。見出しで AI／擬似生成／ルールベースを区別。「AI要約を再生成」「ルールベースを表示」 | 根拠をたどる・区別する |
| カード・タイムライン | 実データの件数・最小最大・症状の推移・回答・質問 | 実データ |

## 7. デモ動画の操作シナリオ（架空データ）
1. 患者A（佐藤 花子）でログイン → 体調記録で今日の体温と「手足のしびれ」を記録 → 診察ノートに質問を保存。
2. 医療者（山田 太郎）でログイン → 「患者との接続を開始」→ QR を表示。
3. 患者がスマートフォンのカメラで QR を読む → 申請者・有効期間を確認 →「この医療者に共有を許可する」。
4. 医療者の画面が診察サマリーに切り替わる →「直近14日間の経過」の要約（AI／根拠つき）を読む → しびれの文を押して根拠の記録（日時・程度）を表示。
5. 「在宅経過」→ 経過表（未記録は —、同じ日の 2 回は ×2）→ セルを押してその日の全記録 →「バイタル統合」で 5 系列を重ねて表示、凡例で脈拍を消す、点にカーソルで実測値・単位・日時。
6. 「期間を確認・変更」で期間を変える（前回外来日を推測しない説明）。
7. 何も入力せず「共有終了」→ 患者情報が画面から消え、再表示には新しい承認が必要。
