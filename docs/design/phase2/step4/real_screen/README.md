# 外来間要約の実画面検証（Claude 実 API）— 2026-11-04

## 2 回目の検証（承認された追加 1 回）— 結果: **生成失敗 → ルールベースの代替表示**
- 隔離環境: `scripts/e2e-server.mjs` の一時 DB（架空アカウント 11 件すべて @example.com を確認）・ポート 3500。実 API、SDK の自動再試行なし（`CLAUDE_MAX_RETRIES=0`）、サーバー全体の呼び出し上限 3（`CLAUDE_MAX_CALLS=3`。要約 1・教材生成 2）、要約の上限 1（`INTERVISIT_AI_MAX_CALLS=1`）、ジョブの再試行なし（`AI_JOB_MAX_ATTEMPTS=1`）。
- 送信: 構造化データだけ（出来事 ID・日時・値・質問の原文）。氏名・メールは送らない。
- 手順: 患者A（佐藤 花子・架空）と山田医師（架空）で QR 共有 → 診察サマリー（`scripts/real-intervisit-screen.mjs`）。最初の要約の応答を待ってから判定・撮影し、**共有終了の前に**画面・応答・根拠を保存。

### 同時要求の統合・重複送信防止の確認
- サーバーのログで、Claude の呼び出しは **1 回だけ**（`[claude] call 1/3 schema=intervisit_summary`）。開発モードの二重読み込みでも画面からの初回の要求は 1 件（`request_count.txt`）。
- 応答（21.3 秒）: `status: fallback`、理由「AI 要約を生成できませんでした（API_ERROR）」。トークン数は失敗のため記録なし。
- 2 件目の要求（在宅経過から診察サマリーへ戻ったとき）は上限により呼び出さずに代替表示（追加の呼び出しなし）。

### 失敗の原因（推定）と対処
- 画面には患者情報を含まない分類コード（`API_ERROR` = Anthropic の API エラー以外の例外）だけを返していたため、詳細な原因はこの実行では記録されていない。
- 推定: 構造化出力のスキーマに書いていた上限（1 文 260 字・根拠 ID 24 件・項目 28 件）は API が保証しない。モデルの出力がこれを超えると SDK の検証で例外になり、要約全体が失敗する。1 回目の検証（インメモリ DB）では 28 項目ちょうどで、上限に近かった。
- 対処（コミット済み・追加の呼び出しなし）: スキーマから上限を外し、サーバー側の検証で 1 項目ずつ判定して超えた項目だけを不採用にする。失敗時はエラーの種類（クラス名）だけをサーバーログに残す。**失敗した結果も同じ共有・期間・データでは再利用し、画面を開き直しても Claude を再度呼ばない**（呼び直すのは「AI要約を再生成」を押したときだけ）。
- **実画面で Claude の要約を表示する検証は、まだ成功していない**。再実行には実 API の呼び出しがもう 1 回必要（承認待ち）。
