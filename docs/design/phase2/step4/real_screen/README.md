# 外来間要約の実画面検証（Claude 実 API・1 回）— 2026-11-04

## 条件
- 隔離環境: `scripts/e2e-server.mjs` の一時 DB（架空データのみ。アカウント 10 件すべて @example.com を確認）・ポート 3500。
- 実 API: `E2E_CLAUDE=real`、SDK の自動再試行なし（`CLAUDE_MAX_RETRIES=0`）、呼び出し上限 1（`INTERVISIT_AI_MAX_CALLS=1`）。
- 送信: 構造化データだけ（出来事 ID・日時・値・質問の原文）。氏名・メールは送らない。
- 手順: 患者A（佐藤 花子）と山田医師で QR 共有 → 医療者の診察サマリーを撮影（`scripts/real-intervisit-screen.mjs`）。

## 結果: 実 API の呼び出しは 1 回行われたが、画面には AI 要約を表示できなかった（ルールベースの代替表示）
- 開発サーバー（React の開発モード）では画面の初回表示で要約の要求が同時に 2 回送られた。1 回目が Claude を呼び（10.1 秒、HTTP 200）、2 回目は上限 1 に達していたため即座にルールベースを返した。画面には先に届いた代替表示が出て、撮影スクリプトもその時点で判定・撮影し、最後に共有を終了したため、Claude の結果（サーバーのキャッシュ）は共有終了とともに破棄され、画面・ファイルに残っていない。
- 追加の実 API 呼び出しは行っていない（上限どおり）。画面の代替表示は設計どおり機能した: 見出し「構造化サマリー（記録から自動整理・ルールベース）」、「AI要約は表示していません：AI 要約の呼び出し回数の上限に達したため、ルールベースで表示しています」、各文から根拠の記録を表示（`03_sources_*`）。
- 原因への対処（コミット済み）: サーバーは同じ共有・期間・データの同時の要求を 1 回の生成にまとめる（進行中の生成を共有）。画面側も同じ期間の要求が進行中なら新しく送らない。撮影スクリプトは最初の要約の応答を待ってから判定する。統合テスト「同時の要求は Claude を 1 回だけ呼ぶ」を追加。
- 再実行には実 API の呼び出しがもう 1 回必要（承認待ち）。
