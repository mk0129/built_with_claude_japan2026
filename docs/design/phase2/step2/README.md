# Phase 2 Step 2 — 情報処方と学習記録を実データへ接続（2026-11-04）

**医療者が教材を処方 → 患者に届く → 患者が学ぶ → 理解確認に回答 → 医療者が学習結果を確認**を、実 API・DB・認証で通した。
画面は Figma Concept D の DOM・CSS のまま、架空データ（`dLessons`・`concerns`・`areas`・`libraryItems` など）を DB の値に差し替えた。
患者画面と医療者画面は同じ記録（`prescription_*`・`learning_progress`・`quiz_*`・`patient_feedback`）を参照する。
医療者の閲覧は Step 1 の有効な一時共有（`requireActiveConsultation`）が必須。

## 1. 実装した機能
### 医療者（/staff、一時共有中）
| 画面 | 実データ |
|---|---|
| 診察サマリー「患者が診察で聞きたいこと」 | 患者の質問（既存 `patient_feedback`）。原文・教材・日時 |
| 「理解を確認したいこと」 | 教材ごとの最新の挑戦の回答（**完了・途中を問わない**）から、誤答と「わからない」を区別して表示。詳細に設問・患者の回答・正答・解説・回答日時・関連教材。回答がなければ「確認問題は未回答です（0% とは表示しない）」 |
| 「領域別の学習・理解確認」 | 処方・自主学習した教材の学習済み／途中／未学習と、確認問題の正答数／回答数、誤答・「わからない」・未学習の件数（Figma の 6 領域に対応づけ）。「医学的理解を断定しません」の注記は Figma のまま |
| 「前回外来からの経過」 | 学習の状況・質問・学習履歴の根拠・学習と質問のタイムラインは実データ。**体調記録（バイタル・自覚症状）は「未接続」**と表示（Step 3・4） |
| 詳しく確認 | 誤答・「わからない」・質問の根拠。関連教材の学習状態。「再処方候補へ」で処方候補に追加。質問は「確認済み／対応済み」を既存 API に記録（任意） |
| 情報処方を作成・教材ライブラリ | 公開・承認済みの教材（共通＋自施設）。**この診察で処方済みの教材は「この診察で処方済み」で選べない**（サーバーも同一セッション同一教材は 1 件）。以前に処方した教材は「再処方に追加」 |
| 処方の確認・確定 | 届け先は実際の患者名。患者へのメッセージ（任意・120 字）は保存し、患者の教材詳細に表示。確定で患者アプリへ反映 |
| 処方完了 | 実際に追加した件数・患者名。「診察を終えて共有終了」はそのまま（入力なしで終了できる） |
| 在宅経過 | Step 3・4 まで「未接続」画面（架空データを出さない） |

### 患者（/home）
| 画面 | 実データ |
|---|---|
| ホーム | 呼びかけ（患者名）・今日の日付・今回（最新）の情報処方（処方元・日付）・続きから再開／新しい教材／すべて学習済み・共有中の相手と残り時間 |
| 今回の情報処方 | 最新の処方セットの教材と処方元 |
| 教材を探す・領域・検索 | 公開教材（共通＋処方を受けた病院の独自教材）と処方済み教材。領域ごとの件数。処方・自主の別と学習状態の絞り込み（既存の自主学習を維持） |
| 教材の詳細 | 要約・学習目標・ページ数・設問数・処方元とメッセージ |
| 学習 | 実際のスライド（見出し・要点・本文・詳しく）と、**承認済みの図解だけ**（未承認は URL も来ない既存仕様）。ページ送りごとに位置を保存し、閉じても再読み込みしても続きから。音声は端末の読み上げ機能でスライドの読み上げ文を読む |
| 理解確認 | 実際の設問を 1 問ずつ。選んだだけでは記録せず「この回答で確定する」で記録（既存 API）。「わからない」は誤答と別に記録 |
| 解説 | サーバーの採点結果と解説、誤答・「わからない」は正解を表示、関連ページへ戻る。残りがあれば「次の問題へ」。再読み込みしても同じ解説（URL の `q`） |
| 振り返り | 教材名・ページ数・回答数／振り返りたい件数・学んだ教材数 |
| 学習記録 | 学習済み・途中の件数、領域別の状況、最近学んだ教材 |

## 2. 変更した DB・API・ファイル
- **DB スキーマの変更なし**（既存の `prescription_items.note` を処方メッセージに使用）。
- API
  - 新規 `GET /api/v1/library`（患者本人のみ）: 教材一覧＋処方元（医療者名）・メッセージ・学習目標。
  - `GET /api/v1/consultations/:id/patient`（既存）に `answers`（最新の挑戦の回答。誤答・わからない・正答・解説・日時・教材）、`learning[].objective/versionId/slideCount/questionCount/completedAt`、`patientName` を追加。
  - `POST /api/v1/consultations/:id/prescriptions` に任意の `note`（120 字まで）。
  - `GET /api/v1/consultations/:id/materials` に `objectives`。質問一覧に `primaryDomain`。
- サービス: 新規 `src/server/services/learning-record.ts`（`listLatestAnswers`）。`consultation.ts`・`library.ts`・`prescription.ts`・`materials.ts`・`questions.ts` に項目追加。
- 画面: 新規 `src/concept-d/learning.ts`（患者の教材・学習・理解確認のフック）、`src/concept-d/record.ts`（医療者のサマリー・処方のフック）。`PatientD.tsx`・`ClinicianD.tsx` は `learning` / `record` があるときだけ実データを使い、ないとき（開発用 /d/dev）は Figma の架空データのまま。
- テスト: `tests/e2e/prescribe_learn.spec.ts`（新規）、`tests/integration/learning-record.test.ts`（新規）。
- 比較: `scripts/concept-d/compare.mjs` は患者画面を /d/dev（同じコンポーネント＋Figma のデータ）で撮るよう変更（本番 /home は実データのため）。

## 3. 既存バックエンドの再利用
処方（同一診察 1 セット・同一教材 1 件・通知・監査）、版の固定（処方時の版で学習）、学習位置の保存、挑戦の固定と 1 問ずつの回答確定・回答変更不可、「わからない」の別集計、採点、宿題スナップショット（診察開始時に確定）、質問の状態記録、自主学習の可否判定、承認済み図解の配信、`requireActiveConsultation` による 403 — すべて既存のまま使用。

## 4. Figma UI から変えた箇所と理由
| 箇所 | 変更 | 理由 |
|---|---|---|
| 学習画面のボタン | 最後のページ以外は「次へ」、最後は「理解を確認する」（設問がなければ「学習を終える」）。ページ数「n / N」 | 実教材は複数ページ（Figma は 1 ページ固定） |
| 学習画面「医療機関へ相談する目安」 | 本番では出さない | 手術後の腕に固有の架空の医学的文言で、教材ごとに確認されていない |
| 学習画面「もう少し詳しく」 | 教材に「詳しく」がないページでは出さない | 空の開閉を置かない |
| 解説「確認したいポイント」 | 誤答・「わからない」のとき「正解は「…」です」 | 架空の文言の代わりに実際の正答 |
| 解説のボタン | 残りの設問があれば「次の問題へ」 | 実教材は複数問 |
| 振り返り「体調を記録した日」「診察につなげた質問」 | 「—」 | 体調記録・診察ノートは Step 3 まで架空データ（実データと並べない） |
| ホーム「次回診察」 | 「次回診察日：未登録」 | DB に次回診察日がない |
| 医療者の教材カード「対象者」 | 「未登録」 | 教材に対象者の項目がない |
| 「領域別」の内訳 | Figma の固定値の代わりに件数 | 実データ |
| 医療者「前回外来からの経過」 | 体調の 2 枚は「未接続」、期間変更ボタンなし、タイムラインは学習・質問だけ | 体調記録は Step 3・4 |
| 「詳しく確認」の任意メモ・理解確認項目の状態ボタン | 本番では出さない（質問の状態ボタンは既存 API に記録） | 保存先がなく、保存したように見せない |
| 在宅経過 | 「未接続」画面 | Step 3・4 |
| 上部の表示 | 「体調記録・診察ノートは架空データ（未接続）」「在宅経過・教材スタジオは架空データ（未接続）」 | 接続済みの範囲が広がったため、未接続の範囲だけを示す |

## 6. テスト結果
- 型検査: エラー 0。ESLint: エラー 0（警告 4 はいずれも既存: Figma 由来・seed の未使用変数）。
- Vitest: 11 ファイル・72 件合格（新規 `learning-record.test.ts` 2 件: 処方 → 患者一覧 → 「わからない」と誤答（途中の挑戦）→ 次の共有で回答・正答・解説・日時・教材を確認 → 終了後 403、同一診察の重複処方なし、メッセージ 120 字制限、患者一覧は本人のみ）。既存の宿題スナップショット・版管理・再処方・認可のテストはそのまま合格。
