# Phase 2 Step 1: QR 一時共有（2026-11-03）

基準: `ed21cc8`（Figma Make Concept D を正式 UI に切り替えた時点）。画面（DOM・CSS）は変えず、Figma の架空の共有状態を実 API に置き換えた。

## 流れ

1. 医療者（`/staff`）「患者との接続を開始」→ 接続申請を発行し、実際の QR を表示（Figma のプレースホルダー枠の中。5 分で失効し、自動で新しい QR に差し替え）。
2. 患者がスマートフォンのカメラで QR を読む → `/home?view=share&connect=<token>`（未ログインならログイン後に同じ画面へ）。
3. 患者の「医療者との一時共有」画面に申請者（医療機関・医療者名）を表示 → 「一時共有の内容を確認しました」→「QRを読み取って共有を開始」で明示承認。
4. 医療者画面は承認をポーリングし、通常の `/staff` で診察サマリーへ（`?s=<セッション>`。再読み込みでも同じ共有に戻る）。ヘッダーの患者名・残り時間は実データ。
5. 延長: 医療者「共有を延長」→「患者の再承認待ち」→ 患者に通知 → 同じ確認画面で再承認 → 医療者に「再承認しました」。
6. 終了: 患者「一時共有を終了する」または医療者「共有終了」で即時終了。医療者画面は「一時共有は終了しました」に切り替わり、API は 403。

6 桁コード（既存の代替手段）: 医療者が「6桁コード」に患者アプリのコードを入力 → 患者が承認 → 同じく診察サマリーへ。

## 新旧フローの比較と安全設計

| 観点 | 患者発行 QR（既存、6 桁コードで維持） | 医療者発行 QR（新規） |
|---|---|---|
| QR・コードを表示する人 | 患者 | 医療者 |
| 承認前に医療者へ渡る情報 | なし | なし（申請状態とセッション ID のみ） |
| QR が第三者に読まれた場合 | 読んだ医療者が「読み取り要求」を出せる → 患者が要求者を見て承認／拒否 | 読んだ患者が「自分の情報をその医療者に共有するか」を判断するだけ。第三者の情報は漏れない |
| 承認前に患者が確認するもの | 要求した医療機関・医療者 | 申請した医療機関・医療者（`connect/preview`） |
| トークン | 5 分・1 回限り。ハッシュのみ保存 | 5 分・1 回限り。ハッシュのみ保存。医療者 1 人につき有効な申請は 1 つ（再発行で旧申請は取り消し） |
| セッション | 60 分。延長は患者の再承認。どちらからでも即時終了 | 同じ処理（`startConsultationSession` に共通化） |

- 新テーブル `connect_requests`（マイグレーション `0009`）。承認前は `patient_id` が空。承認時は既存の `qr_grants` に承認済みの行を作り、`consultation_sessions.qr_grant_id`（必須）と監査をそのまま使う。
- 医療者の患者一覧は持たない: `/staff` が参照するのは「この医療者のいま有効な共有」1 件だけ。終了・期限切れの共有の患者名は返さない（`patientName` は共有中のみ）。
- ログイン後の戻り先（`returnTo`）は同一サイトの相対パスのみ（`//` で始まる外部 URL を拒否。医療者ログインも同様に修正）。

## 画面上の変更（報告）

見た目・CSS は変えていない。以下は「表示する値・操作の中身」を実データにしたもの。

| 画面 | 内容 |
|---|---|
| 医療者「患者へ接続を申請」 | QR のプレースホルダー（アイコン）→ 実際の QR 画像（同じ枠の中）。Figma との画素差はこの枠の中だけ |
| 医療者ヘッダー・サイドバー | 患者名（頭文字）・残り時間（「残り 59:58」「残り60分」）が実データ。「52歳 · 乳房部分切除術後 · 次回診察 6月20日」は DB にないため Figma の文言のまま（Step 2 以降） |
| 患者「医療者との一時共有」 | 説明文（`.d-share-intro`）に申請者を表示（「さくら総合病院（架空） 山田 医師が閲覧を申請しています。…」）。延長申請時は「…が共有時間の延長（60分）を申請しています。…」 |
| 患者「一時共有中」 | 共有先・残り時間・見出しの医療者名が実データ |

確認していただきたい点:

1. 患者の承認ボタンの文言は Figma の「QRを読み取って共有を開始」のまま。QR はカメラで読んだ後なので、実際の操作は「承認」。延長の再承認にも同じボタンを使っている。文言の変更（例「共有を承認する」）は未実施。
2. QR を読まずにボタンを押した場合は「スマートフォンのカメラで、医療者の画面に表示されたQRコードを読み取ってください」と案内するだけ。アプリ内のカメラ読み取りは、新しい画面要素（カメラ表示）が必要で、iPhone では HTTPS が必要なため未実装。
3. 6 桁コード: 医療者側の入力は接続済み。患者アプリにコードを表示する画面が Figma にないため、患者側の表示は未実装（API `POST /api/v1/qr` は既存のまま）。
4. 所属先が複数ある医療者は、診療権限のある最初の所属先で申請する（Figma に所属先の選択がない）。
5. 診察サマリーの中身（質問・理解確認・在宅経過など）は Step 2 以降で接続するまで Figma の架空データ。「架空データ」の表示を残している。
