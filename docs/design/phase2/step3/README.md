# Phase 2 Step 3 — 体調記録・診察ノートを実データへ接続（2026-11-04）

患者が自宅で残す体調記録と質問を DB に保存し、Step 1 の QR 一時共有の間だけ医療者が読めるようにした。
画面は Figma Concept D の DOM・CSS のまま、架空の記録（`initialHealthRecords`）・質問メモの代わりに DB の値を渡す。

## 1. DB スキーマ（`0010_step3_health_notes.sql`）
| テーブル | 内容 |
|---|---|
| `health_records` | 1 回の測定 = 1 行（同じ日に何回でも独立）。体温・収縮期/拡張期血圧・脈拍・SpO₂ はすべて NULL 可（未測定）。`measured_at`（患者が入力した測定日時）・`created_at`・`updated_at` を区別 |
| `health_symptom_entries` | 記録ごと・症状ごとの程度 0〜4（CHECK 制約）と回数・部位・日常生活への支障。**回答しなかった症状は行を作らない（欠測）**。保存時の症状名を残す |
| `patient_symptom_settings` | 患者ごとの表示する症状・並び順・非表示（`hidden`。行は消さない）・独自の症状名 |
| `visit_notes` | 診察ノートの質問。`source`＝free / quiz。理解確認から作った質問だけ教材・版・設問を保持。自由な質問は教材なし |

既存の学習後フィードバック（`patient_feedback`）はそのまま残す。

## 2. API
| API | 権限 |
|---|---|
| `GET/POST /api/v1/health/records`、`PATCH/DELETE /api/v1/health/records/:id` | 患者本人のみ（他の患者の記録は 404） |
| `GET/PUT /api/v1/health/symptoms` | 患者本人のみ |
| `GET/POST /api/v1/notes`、`PATCH/DELETE /api/v1/notes/:id` | 患者本人のみ。教材付きの質問は、患者が回答した設問・学習できる版に限る |
| `GET /api/v1/consultations/:id/health`（新規） | 医療者。有効な診察セッションのみ（Step 4 の経過表・要約で使う取得 API。監査記録あり） |
| `GET /api/v1/consultations/:id/patient`（既存） | `visitNotes` を追加 |

サーバー側の検証: 値の範囲（体温 30–45、血圧 50–260/30–160、脈拍 20–250、SpO₂ 50–100）、未来の測定日時の拒否、程度 0〜4、症状 ID（ライブラリ or `custom-…`）。記録しても医療者へ通知しない。

## 3. 患者側の操作
- 体調記録: 新しい記録は**今の日時・すべて空欄**から（前回値を入れない）。保存ごとに別の記録。未回答の症状は「未回答（欠測として保存）」のまま送らない。詳細（回数・部位・支障）も保存。
- 履歴・グラフ: 「n日分・m件」。記録ごとに「この記録を編集」「この記録を削除」（確認してから削除）。症状に回答がない記録は「自覚症状：回答なし（欠測）」。推移は表示中の症状＋記録のある症状から選べる。
- 症状の設定: ライブラリから追加、自由入力の症状を追加、非表示（過去の記録は残る）、並び替え。再ログイン後も維持。
- 診察ノート: 質問の作成・編集・削除、保存日／更新日、教材由来の質問は「教材「…」から」。
- 理解確認の「この内容から質問候補を作る」: 候補を診察ノートの入力欄に入れるだけ。患者が確認して「質問を保存」を押したときに初めて記録（教材・版・設問付き）。
- ホーム: 質問メモの件数、体調の前回記録日（未記録なら「まだ記録はありません」）。振り返り・保存後の集計も実データ。

## 4. 医療者側へ反映したもの
- 診察サマリー「患者が診察で聞きたいこと」: 診察ノートの質問（教材に紐づかないものを含む）と、既存の学習後の質問を統合。自由な質問は「関連教材：なし（自由な質問）」。診察ノートの質問には状態ボタンを出さない（閲覧だけで終われる）。
- 「前回外来からの経過」: 質問の件数・原文・タイムラインに診察ノートを含める。**体調記録の経過表・要約は「未接続（Step 4 で表示）」のまま**。在宅経過の画面も未接続のまま。
- 共有終了・失効後は、質問・体調記録の API とも 403。

## 5. 既存実装の再利用
認証・`requirePatient`・`requireActiveConsultation`（有効な診察セッション）・監査ログ・学習可否の判定（`assertPatientHasVersion`）・QR 一時共有・診察サマリー API・症状ライブラリ（Figma の `symptomLibrary`）。

## 6. 視覚的な変更
| 箇所 | 変更 | 理由 |
|---|---|---|
| 患者画面の上部「架空データ」表示 | **出さない** | 患者画面はすべて実データになったため。全画面の学習・解説・振り返りで見出しに重なっていた問題もこれで解消（画像 10） |
| 体調記録の保存ボタン | 「この記録を保存」／編集中は「この記録を更新」＋「編集をやめて新しい記録にする」 | 1 回の測定 = 1 記録（Figma は 1 日 1 記録で同じ日を上書き） |
| 測定日時 | 初期値は今の日時、未来は選べない | 前回値・Figma の固定日付を使わない |
| 履歴の記録 | 「この記録を編集」「この記録を削除」（Figma の `.d-text-action`）、件数「n日分・m件」、回答なしの表示 | 編集・削除の要件、同じ日の複数回 |
| 診察ノートの次回診察 | 「次回診察日：未登録」＋共有の説明 | DB に次回診察日がない |
| 診察ノートの各質問 | 保存日／更新日・元の教材を小さく表示 | 作成・更新日時と教材由来の区別 |
| 医療者の上部表示 | 「在宅経過は未接続（Step 4）・教材スタジオは架空データ」 | 範囲の更新 |

## 8. Step 4 へ引き継ぐ課題
- 医療者の在宅経過表・「前回外来からの経過」の体調部分は未接続表示のまま。`GET /api/v1/consultations/:id/health` で記録と症状の設定を取得できる（期間指定 `from`/`to`）。
- 「前回外来」の日付は DB にないため、Step 4 では前回の共有日時を既定にし医療者が期間を選ぶ設計が必要（日付を推測しない）。
- Claude による外来間要約は、出典（記録 ID・回答・質問）をたどれる形で、架空データのみで検証する。CTCAE Grade・因果関係・診断を出さない。
- 症状名の変更（独自の症状）は現在できない（追加時に確定）。
