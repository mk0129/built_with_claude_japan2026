# 画像アセット納品時のQA・実装取り込みルール

## ファイル生成
- ChatGPT画像生成で**1回につき1主題・1ファイル**を基本とする。複数主題を一枚にまとめたアセットシートやUIモックの切り抜きは制作完了と扱わない。
- 生成後に実際のファイルを開き、内容が仕様と一致するか**画像を目視**して確認する。自動生成された図解・人体を医学的に正確と見なさない。
- 指定解像度に合わせて出力し、透明背景のPNGで保存する。生成結果を別途画像処理した場合は白ハロー、線消失、水彩欠けを検査する。

## ファイル単位で確認すること
- [ ] `asset_id`とファイル名がマニフェストと一致する。
- [ ] 透過背景が成立している（隅のRGBA、背景の不自然な白残り、プレビューでの実見）。
- [ ] 色や線の質感がC案の落ち着いたデザインに合う。
- [ ] 文字・数字・記号・ウォーターマークが画像に混入していない。
- [ ] 人体部位、医療器具、診療場面に違和感がない。
- [ ] 医学的関係性が原資料と一致する（MEDのみ、医療者による承認必須）。
- [ ] 390pxの患者画面で内容が伝わり、注釈をコード側で読める。
- [ ] VoiceOver等で内容を説明できるalt/long descriptionが設定されている。
- [ ] 画像利用権・AI生成元・制作日・版を記録した。
- [ ] 医療者監修済みでないものはプレビュー以外に出ない。

## コード取り込み
1. 完成画像を `public/assets/medical/` または `public/assets/editorial/` に個別ファイルとして配置。
2. `asset_id`からファイルへの対応をデータに登録。
3. 画像ラベルや矢印をHTML/SVGで配置。レスポンシブ表示・テキスト拡大を検証。
4. 医療者による監修完了まで `review_status=pending` として患者教材へ配信しない。
5. 画像が欠ける場合、学習目標を伝える監修済み文章を代替表示する。
6. 医学的な内容が変わる改訂では画像も対象とし、承認なしに旧画像を使い回さない。

## 注意したい落とし穴
- 医学図解は「イラストの雰囲気が良い」だけでは採用しない。病期分類、治療適応、相談基準は専門職が原資料と照合する。
- 一枚絵の構成が小画面で窮屈になる場合は、絵をむやみに縮小せず、複数の図または複数画面へ分割する。
- 未完成の絵に `監修済み` ラベルを付けない。
- 医学的な正誤や治療選択はAIが自動判断しない。
