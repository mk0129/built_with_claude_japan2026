## 2. 機能の維持（参照 HTML の架空処理は採用していない）

| 要件 | 実装 |
|---|---|
| 1 問 1 画面、3 択＋「わからない」 | 既存の attempt / questions をそのまま表示。「わからない」は破線の 4 つ目 |
| 選択と回答確定は別操作 | 選択肢は `role=radio` で選ぶだけ（POST なし）。「回答を確認する」で `POST /attempts/{id}/answers`。E2E で選択時 POST 0、確定時 1 を確認 |
| 回答後は穏やかな説明 | 「確認できました。」「一緒に振り返りましょう。」「「わからない」を記録しました。」＋解説、誤答は正解を併記、関連画面へのリンク |
| 保存中の表示 | 確定後は押した選択肢が `pending`（記録中…）、他は `dim`、CTA は「記録しています…」。失敗時は「もう一度記録する」 |
| 採点・履歴・スナップショット | サーバーのロジック・API は不変（Vitest 61 件合格） |
| 点数を主役にしない | 結果はアイコン＋「ここまで学べました」＋ 確認できた／もう一度確認／わからない の数。点数は「点数を見る」の折りたたみ |
| 質問の明示的な保存 | テーマ（誤答・わからないの関連画面タイトル、または「自分で書く」）を選ぶと候補文が入力欄に入り、患者が編集。「次の診察に残す」を押したときだけ `POST /api/v1/feedback`。4 択の気持ちは任意（未選択なら質問文ありで「質問がある」、なしで「もう一度説明してほしい」） |
| 緊急窓口ではない旨 | 箱の末尾と保存後に表示 |
| もう一度挑戦・読み直し | 「次にできること」に維持（`forceNew` の再挑戦） |

## 4. 未解決・判断点
- テーマチップの文言: 教材の画面タイトル（6〜8 文字）をそのまま使っている。参照のように 5 文字程度に揃えるなら、教材データに短いテーマ名を持たせる必要がある（Phase C 以降の判断）。
- 質問の箱の注記（明示保存の説明）は参照に無い。短縮または保存ボタン直下に移すことは可能。
- 820 / 1180 は 448px 中央寄せ。

## 5. テスト結果
- TypeScript / ESLint エラー 0（既存 warning 1）、Vitest 61 件合格。
- Playwright: `quiz_result`（390/430: 選択で POST 0 → 確定で pending → 正解／誤答／わからない → 結果のタイル・テーマ・編集・明示保存 1 回・文字拡大）、`cta`、`flow`（処方 → 学習 → クイズ 3 問 → 中断再開 → 再挑戦 → 質問保存 → 次回診察）、`c2_screens`、`ux_audit`、`real_generation`（擬似）合格。`reset_phase_b`（撮影・計測・最下部の被り検査）合格。
- 更新した期待値: 選択肢は `role=radio` → 「回答を確認する」で確定、「確認を終えました」→「ここまで学べました」、「結果を見る」→「学びの結果を見る」、「確認問題 n / N」→「QUESTION 0n」。
