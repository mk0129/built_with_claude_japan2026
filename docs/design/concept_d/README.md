  - `ClinicianD.tsx` `healthData.ts`: 複製。`figma.css`: `index.css` の複製（無加工）。

    2. 型の区切り記号の欠落 2 か所と、型の絞り込み 1 か所の修正（Figma の Vite は通るが `tsc` が通らないため）。
    3. `variant`（`app` / `prototype`）の追加。`app` では検証シナリオ・テスト状態・Before/After を出さず、端末枠に `d-device-app` / `cd-device-app` を付ける。

## 過去の仕様・既存実装との差分（Phase 2 の前に決めたいこと）

1. **QR の向き**
   - Figma: 医療者の画面に QR を出し、患者アプリで読み取る。6 桁コードは「患者アプリに表示されたコードを医療者が入力」。
   - 既存: 患者が QR とコードを出し、医療者が読み取る。
   - 6 桁コードの向きは既存と同じだが、QR は逆。
2. **動きの効果**
   - Figma には回答後のフィードバックの穏やかな表示（`d-gentle-in`）と「動きの効果：オン／オフ」がある。`prefers-reduced-motion` では止まる。
   - 以前の方針「モーションアニメーションは実装しない」と衝突する。今回は Figma を正本として、そのまま残した。
3. **診察ノート**
   - Figma の質問は教材に紐づかない自由記述（追加・編集・削除）。
   - 既存の `patient_feedback` は教材版が必須のため、テーブルの変更が必要。
4. **医療者の記録**
   - Figma は「確認済み／対応済み」「補助メモ」をすべて任意にし、文章入力なしで共有を終了できる（二重記録をしない原則）。
   - 既存の診察画面の記録フォームは、この原則に合わせて任意に寄せる。
5. **Figma の擬似操作**
   - 「プロトタイプ：患者が承認」「プロトタイプ：再承認」は Phase 2 で実際の承認待ち（ポーリング）に置き換える。
   - Phase 1 では Figma どおり表示している。
6. **体調記録・在宅経過・外来間サマリー**: DB がない（PLAN §6）。
7. **患者名や日付**: 「佐藤さん」「6月14日」などは Figma の架空データのまま（Phase 2 で実データに置き換え）。

# 正式 UI への切り替えと医療者 UI の修正（2026-11-03 追記）

## 原因

| 指摘 | 原因 |
|---|---|
| 通常の localhost で旧 UI が出る | ログイン後の遷移先（患者 `/home`、医療者 `/staff`）が旧 UI のままで、Figma 版は別 URL `/d/*` に追加しただけだった |
| `/d/clinician` が Figma と違う | 本番表示で端末枠を「画面いっぱい」にしていたため、1180px で設計された医療者画面が 1440px などの PC 画面で横に引き伸ばされていた。Figma は 1180px（または 820px）の画面を中央に置く。比較は 1180×800 ちょうどで撮っていたため検出できなかった（患者も PC 幅ではタブレット表示が全幅に伸びていた） |
| 本番に架空の操作がある | 「プロトタイプ：患者が承認」「プロトタイプ：再承認」（医療者）、「QRを読み取って共有を開始」で即座に共有中になる（患者）が本番にも出ていた |

`/d/dev` は Figma と一致していた（`switch/figma_clinician_active_1440.jpg` と同じ構成）。

## 修正

- **設計幅を保つ**（`src/concept-d/app.css`、端末内には触れない）
  - 患者: 700px 以下は端末枠なしの全画面（Figma 自身の扱い）、それより広い画面は Figma のタブレット表示 768px を、Figma のステージと同じ背景・角丸・影で中央に置く。
  - 医療者: 1180px 以上は 1180px、未満は 820px の画面を中央に置く（画面が狭いときは全画面）。
  - 高さだけは画面に合わせる（端末内は Figma どおりスクロール）。
- **本番に架空の操作を出さない**
  - 医療者: 「プロトタイプ：患者が承認」「プロトタイプ：再承認」は開発用 `/d/dev` だけに表示する。本番は承認待ちで止まり、一時共有中の画面は Phase 2（既存の QR・承認 API への接続）まで表示されない。
  - 患者: 「QRを読み取って共有を開始」は本番では共有中にせず「準備中（実データ未接続）」と知らせる（見た目は Figma のまま）。
  - 画面上部に「プロトタイプ表示・架空データ（実データ未接続）」（スマートフォンは「架空データ・未接続」）を重ねて表示する。レイアウトに影響しない重ね表示で、Phase 2 で実データにつないだら外す。
- **正式 UI へ切り替え**
  - 患者 `/home`、医療者 `/staff` が Figma 版。`/` はログイン済みなら役割に応じて転送。
  - 旧 UI の画面は `legacy/reset01-ui/app/` に退避（配信・型検査・lint の対象外。削除していない）。旧 URL（`/library` `/learn/*` `/quiz/*` `/scores` `/share` `/staff/consult/*` `/staff/studio/*` `/staff/scan` `/staff/materials/*` `/c` `/d/patient` `/d/clinician` `/pb/*` `/design/*`）は新 UI へ転送。
  - ログイン画面と未ログイン時の入口は Figma にデザインがないため、従来のものを残した（旧 UI のタブ・サイドバーは外した）。
  - 患者画面の状態（画面・教材・領域）を URL（`?view=` `&lesson=` `&area=`）に持たせ、再読み込み・戻る／進むで同じ画面に戻る。医療者は本番で一時共有が始まらないため、URL には持たせていない。
- **変更していないもの**: 認証、API（`src/app/api`）、DB、サービス層、権限チェック。
