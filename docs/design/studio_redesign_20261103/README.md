# 教材スタジオ 再設計案（情報設計・ワイヤーフレーム）2026-11-03

範囲: 情報設計とワイヤーフレームまで。スタジオ全体の再実装は行わない。
ワイヤー: `wireframes.html`（静的 HTML、アプリとは独立）。画像: `wf1`〜`wf6`。

## 1. 設計の軸

- **主役は 6 ステップの制作フロー**。画面上部に常にステッパーを置き、「いま何をしていて、次に何をするか」を示す。
  1. 原資料を選ぶ → 2. Claude が学習目標と構成案を提案 → 3. 医療者が構成案と必須事項を確認 → 4. Claude が教材とクイズを生成 → 5. 患者画面でプレビュー → 6. 原資料と照合し編集・承認
- **主な利用環境は PC・タブレット**（1180 / 820）。原資料と Claude の提案（または教材と患者画面）を**同じ画面に横並び**で置く。スマホ（390）は 1 列で破綻しないことを優先し、作成中の進捗はボタン直下に出す。
- **見せ場 = 構成案の提示（ステップ 2）**。原資料の段落が左に、Claude の 3 案が右に並び、案に触れると根拠段落が強調される。案は「学習目標・画面構成・根拠段落・この案の特徴」で違いが読める。「おすすめ」は原資料の先頭章に基づく案（Day 5 の案 1 に相当）。
- 承認前の点検（引用一致・必須事項の網羅・原資料にない語）を**承認ボタンの直前ではなく画面の最上段**に置き、未網羅があれば「追記する／理由を記録して承認する」の二択にする（承認はブロックしない）。

## 3. 情報階層（原資料・生成結果・履歴を混同しない）

```
原資料（ソース）          ─ 許諾・抽出テキスト・段落番号。読み取り専用
  └ 生成（ジョブ）        ─ 構成案 / 下書き。最新の 1 件を「結果」として大きく、過去は履歴に
      └ 教材（版）        ─ 下書き → 承認待ち → 公開。編集・照合・承認の対象
```
- ステップ 2〜4 は原資料画面の中で進み、ステップ 5〜6 は教材画面（版）で進む。URL も `sources/{id}` と `materials/{versionId}` のまま。
- 履歴は折りたたみ、既定で閉じる（P0 で実装済み）。
