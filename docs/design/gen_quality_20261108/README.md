読んだ印象（監修前の下書きとして）:
- 設問は「A さんは…。どうしますか。」の形で場面が置かれ、誤答が「自分の判断で量を減らす」「朝まで市販薬で様子を見る」など患者が実際に取りがちな行動になった。解説は 正答の理由 → 誤答が不適切な理由 → 原資料の引用 の順で書けている。
- 本文は 1 画面 2〜3 文に収まり、まとめ画面に担当医優先の定型文が入った。
- 必須事項 8 件を 5 画面に収めるため、画面 4 の補足に連絡・相談の項目が集まった。Claude 自身が「監修時に画面を分けるか確認が必要」と `notCoveredBySource` に書いている。必須事項が多い原稿では画面数の上限（5）を 6 にするか、構成案の段階で 2 教材に分ける案が候補。
- 正答が最長の選択肢になる傾向は残る（5 問中 4 問。ただし長さの比は 1.1〜1.18 で、長さで選べる差ではない）。
- 本文の所要時間が 63 秒に伸びた（思考を含む出力が 10k トークン）。公開デモの進行バーは段階表示なので待てる範囲だが、effort を `low` にした比較は未実施。

## 失敗の記録と原因（重要）
最初の 3 回の構成案の呼び出しは、すべて `stop_reason: max_tokens`（32,000 トークンを思考だけで消費、本文 0 文字）で失敗した。原因はプロンプトではなく、Claude Code の作業シェルが持つ `CLAUDE_EFFORT=max` がアプリに漏れ、`output_config.effort: "max"` で呼んでいたこと（`claude.ts` は `CLAUDE_EFFORT` をそのまま使う）。`CLAUDE_EFFORT=medium` を明示して成功した。対策として、未設定時の既定を `medium` にし、`max_tokens` 到達時に内訳をログに出すようにした。ローカルで実 API を使うときは `CLAUDE_EFFORT` と `CLAUDE_MAX_CALLS` を必ず明示する。

実 API の呼び出し: 承認された上限 8 回のうち 6 回（成功 2、`max_tokens` で失敗 3、設定誤りの 400 が 1）。費用の目安は Sonnet 5.5 の単価（入力 $2 / 出力 $10 per 1M）で、失敗 3 回の出力 96k トークン ≈ $0.96 を含めて合計 約 $1.2。
