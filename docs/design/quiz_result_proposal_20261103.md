# クイズ・結果画面の改善案（2026-11-03）

- プレビュー: `/design/quiz-result/{versionId}?variant=current|proposed`（結果）、`&screen=question`（回答直後の見え方）。医療者のみ。本番 `QuizClient`、採点・回答履歴・スナップショットのロジックは未変更。
- 画像: `compare_20261103/result_{current|proposed}_{390|430}_{first|full}.png`、`result_proposed_*_selected.png`（質問候補を選んだ状態）、`question_pending_{current|proposed}_{390|430}.png`
- データ: MED-001 の実際の 3 問に、架空の回答（正解 1・誤答 1・わからない 1）を当てている。

## 現行の課題（監査 p21〜p24）
- 回答タップ後、保存完了まで押した選択肢に変化がない（他が薄くなるだけ）。
- 結果画面は「もう一度確認できるところ」→「次にできること（正解 n/N）」→「次の診察で聞きたいこと（4 択＋自由記述＋送る）」の順で、質問の導線が最下部（390 で約 2 画面分下）。
- 「確認できた 1 ／ ！1 ／ ?1」のピルは意味が記号頼み。

## 改善案の構成（上から）

| 順 | 区画 | 内容 | ねらい |
|---|---|---|---|
| 0 | 見出し | 「確認を終えました。おつかれさまでした。」＋ 3 枚のタイル「理解できた n／もう一度 n／わからない n」（色面＋文字。点数なし） | 大きな点数に依存せず、今回の状態を 1 行で |
| 1 | **次の診察で先生に聞く**（強調枠） | 誤答・「わからない」の設問が質問候補として並び、タップで ✓。4 択は 2 列、自由記述は何か選んだ後に展開。「質問 n 件を先生に送る」 | 価値の中心（理解できなかったことを次の診察へ）を最上段に。既存の `/api/v1/feedback`（selection＋freeText）のまま、候補の設問文を freeText に連結して送る想定 |
| 2 | もう一度確認したいこと | 設問ごとに「あなたの答え（取り消し線）／正解（太字）」を並べ、解説を折りたたまず表示、「n 画面目を読み直す」を全幅ボタンに | 誤答・わからないを振り返りやすく |
| 3 | 今回理解できたこと | ✓ 付きで正解した内容（正解の選択肢文）を列挙 | 肯定的に締める。空のときは「読み直してからもう一度」 |
| 4 | 次にできること | もう一度挑戦する／説明をはじめから読み直す。点数は「点数を見る（先生と確認する材料です）」の折りたたみ | 既存の操作を維持 |

回答直後（保存中）の見え方: 押した選択肢を即座に「選択中…」（濃い枠・面色）にし、他の選択肢を薄くして「記録しています…」を表示。失敗時は同じ場所に再送ボタン（UX-08、本番は `busy` 中に `data-state="pending"` を付けるだけで実装できる）。

## 実装時の注意（本番反映する場合）
- `FeedbackForm` の送信 payload は変更しない。候補設問は `freeText` の先頭に「【確認したい問題】…」として連結する（医療者画面の既存表示でそのまま読める）。
- 「わからない」と誤答の区別は既存の `isUnknown` を使う。採点・`scorePct`・スナップショットには触れない。
- 見積: 結果画面 3h、回答直後の選択状態 1h、E2E の期待値更新 1h。
