## 4. 診察画面の質問行: 2 行表示＋展開の UI 案

モック: `proposals/question_row_2line.html`（静的 HTML、製品コードではない）、画像 `proposals/question_row_2line_640.png`、`_390.png`。

| 案 | 内容 | 行高（640 / 390） | 評価 |
|---|---|---|---|
| 現状 | 日付・教材・気持ちの行、全文、ボタン 2 つ | 211 / 255 | 1 件でも参照の 2.6 倍 |
| A 案 | 本文を 2 行に省略（CSS `line-clamp`、文字拡大時 3 行）＋「全文を読む」。メタ情報は見出し行へ（「患者からの質問 ・ 11月3日 ・ 病期の考え方」）。ボタン 2 つは維持 | 199 / 222 | 変更最小だが削減は 1 割程度。ボタン行が高さの主因 |
| **B 案（推奨）** | 2 行省略＋行の右端に「対応する ›」（44px）。展開すると全文・対応の方法・「対応済みとして記録する」「関連教材を候補へ」が行内パネルに出る。未確認タグは折りたたみ時も表示 | 110〜133 / 157 | 参照 81px に最も近い。質問が複数でも「確認したいこと」の全体が 1 画面に収まる |

B 案の実装方針（着手は指示後）:
- `QuestionRow` の表示を「折りたたみ／展開」の 2 状態にし、既存の記録フォーム（確認済みにする・対応の方法・一言メモ・対応済みとして記録する）と `prescribeRelated` はそのまま展開パネル内に移す。API・状態管理は変更しない。
- 展開ボタンは `aria-expanded` `aria-controls`、Enter/Space で開閉。`prefers-reduced-motion` に関わらずアニメーション無し。
- 本文省略は CSS のみ（`-webkit-line-clamp: 2`、`html[data-textsize=large]` 相当のブラウザ拡大では 3 行）。省略された本文は展開で全文を読める。
- 「もう一度説明したいこと」「学習途中の教材」も同じ型（1 行要約＋「再処方を候補へ」を右端）に揃えると、主カードは参照に近い 3 行構成になる。
- E2E への影響: `flow` `c2_screens` `p0_regressions` の「対応を記録」クリック前に「対応する」を押す手順が必要。
