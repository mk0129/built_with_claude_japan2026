## 3. 編集・患者プレビュー・承認

### 編集（`/staff/studio/materials/{id}`）
- 見出し: eyebrow／`.rsd-h1`／状態・範囲・版・生成元のタグ行。右上に「患者画面で確認」の縦型ボタン。ステッパーは状態に応じて ④ 生成・編集 → ⑥ 承認 → 公開。
- 承認前の点検: 4 つの計測タイル（異常があれば暖色、安全上の未確認は赤枠）。必須事項は「確認済み n ・ 未確認 n ・ 別教材 n」のタグと、各項目の種別・分類・確認状態タグ。
- 本文カード: 「患者画面」「理解度の確認」の eyebrow 付きカード。編集機能と出典の照合（原資料の該当箇所へ移動）は維持。
- 原資料と比較: 右カラム（sticky）、資料名をピル表示。

### 承認（編集画面末尾）
- 見出しを状態に応じて「保存と承認依頼」「承認・差し戻し」「公開中の教材」に。
- **承認の条件** チェックリスト: 引用の一致、出典の有無、必須事項の確認（安全上の未確認は赤・太字）、承認条件／医学的な最終確認は承認者。表示のみで、実際の可否はサーバーの判定（`approvalBlock`・安全上の未確認）のまま。
- 主操作は右寄せ 47px（「承認を依頼する」「承認して公開する」）、「差し戻す」は隣の副ボタン。承認権限がない人には「承認権限のある医療者が確認します」。固定表示はしない。
- 監査ログ、承認権限、公開制御、安全上の未確認の了承（理由の記録）は変更なし。

### 患者プレビュー（`/staff/materials/{id}/preview`）
- 患者の学習コンポーネント（`LearnClient`）を `preview` モードで 390px の端末枠に表示。進捗保存（`/api/v1/learn/*`）は呼ばず、最後の「確認問題へ」は無効。未承認の図解は「監修待ち（患者には表示されません）」を付けて表示。固定 CTA は端末枠の下端に収まる。
- 右側に従来の全画面一覧と図解の監修操作（承認者のみ）。
- アクセス制御: ページは `requireMaterialRole`（編集者・承認者）を維持。未承認図解は従来どおり認証付き管理者ルートから配信し、public へは移動しない。患者の学習 API の公開条件は変更していない。

### サイドバー
診察／教材スタジオ／ログアウトのみ（参照 HTML のレポート・権限などは追加していない）。

## 5. デモ動画の撮影に向けた残課題
1. **デモ用の教材を「擬似生成」から実 API 生成済みの教材に差し替える**。擬似生成の教材は本文が原資料の抜き書き（「要点 1」など）で、編集・プレビュー・承認の画面が説得力に欠ける。実 API 呼び出しが必要なので事前に報告して実施する。
2. デモ用の必須事項（安全上の重要事項を含む）がある教材を 1 件用意する。承認前の点検と承認条件の見せ場になる。
3. デモ患者のデータ整理: 診察画面で質問 1〜2 件、誤答・わからない 1 教材、学習途中 1 教材がそろう状態を固定シードにする。
4. 撮影解像度の決定: 医療者画面は 1180×820（iPad 横）、患者画面は 390×844 を推奨。
5. プレビュー内の「あ+」は医療者端末の文字サイズ設定も切り替える（同じ `html[data-textsize]` を使うため）。デモでは触らないか、別途分離する。
