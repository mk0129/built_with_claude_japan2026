**患者側と診察画面は C2 で完成度が高く、大きな作り直しは不要。** 改善の重心は「教材スタジオ」（生成〜承認の分かりやすさ、スマホ表示、開発用表示の露出）と、患者学習の「最初の画面で本文が見えない」点にある。

## 1. 患者ホーム（p01〜p05）
- 良い点: 「次に読むもの」と大きな 1 ボタン（読む・聞く／確認問題の続きから）で次の行動が明確。進捗バー・所要時間で負担感が小さい。390〜820 で横スクロールなし。
- 課題:
  - 未処方（p01）では「共有から QR を…」の説明がカードと下部に 2 回出る。QR 画面へ直接行くボタンがない（下部ナビの「共有」を探す必要）。
  - 緊急時の案内が本文末尾の小さい文字のみ。
- デモ: 「先生から届いた説明」の言い回しは価値が伝わりやすい。

## 2. 教材学習画面（p10〜p13）
- 良い点: 1 画面 1 要点、前へ／次へが下部固定、目次・文字拡大・読み上げあり。
- 課題:
  - **図のある画面では、最初の表示（390・820 とも）に本文が入らない。** 見出し → 要点 → 図の注意書き → 図の切り替え → 図 → 図の注記 → 本文 の順で、本文と読み上げが下に押し出される（p10・p11・p13）。
  - 図ごとの「開発者（医師）による医学的確認を経た…」の注記が毎回表示され、視覚負担が大きい。
  - 読み上げボタンが画面末尾にあり、聞きたい人ほど見つけにくい。
  - タブレット横幅でも 1 カラムで、図が画面の大半を占める。

## 3. クイズと結果（p20〜p24）
- 良い点: 3 択＋「わからない」、回答直後に正解と解説、「この説明を読み直す」導線。結果画面で誤答・わからないの問題に該当画面へのリンク。
- 課題:
  - 回答をタップしてから保存完了まで、押した選択肢に変化がない（p21: 他の選択肢が薄くなるだけ）。通信が遅いと二度押しや不安につながる。
  - 実 API 検証時、クイズ画面の初回表示が白紙で撮影された（読み込み中の表示がない）。
  - 結果画面は「もう一度確認できるところ」「次にできること」「次の診察で聞きたいこと（4 択＋自由記述＋送る）」で縦に長い（390 で約 2 画面分）。
  - 「理解のきろく」（p24）が「33 点」と点数で表示。注意書きはあるが、患者さんには評価されている印象を与えうる。

## 4. 医療者の情報処方・理解確認（s01〜s05）
- 良い点: 「今日の確認事項」（未確認の質問・誤答・未完了）が最上段にあり、各行に「再処方」「関連教材を処方」。テンプレートのまとめて追加で数タップ処方できる。残り時間・延長・終了が常に見える。外来の短時間でも使える。
- 課題:
  - 処方パネル内に開発者向け文言「AI 検索（患者情報を送らない自然言語検索）は後続フェーズで追加します。」が表示される（s03）。
  - パネル内スクロールでタブ（テンプレート／検索）が上に隠れる（s03 で検索欄が上端で切れる）。
  - 医療者ホーム（s01）で役割が英語（`clinician`）。
  - 理解確認スコアの「点数は表示時のみ四捨五入」は医療者に不要な技術的注記。
  - 共有中画面（患者側）の「共有を終了する」ボタンが短時間に再描画され、E2E で 4 回中 1 回クリックに失敗した（要調査。実機での押し損ねの可能性）。

## 5. 教材スタジオ（t01〜t08）
- 良い点: 許諾の記録、原資料との並列比較、引用の自動照合（✓／×）、生成元バッジ、承認者と編集者の分離は医療安全上の価値が高く、デモの差別化要素。
- 課題:
  - **390 幅で横スクロールが発生（80px）**（t02）。ヘッダーが画面幅に収まっていない。
  - スタジオ最上部を登録フォームが占め、「承認待ち」「下書き」「実行中のジョブ」が下に埋もれる（t01）。再訪時に次の行動が分からない。
  - B 方式で「構成案を作る」を押すと、構成案は画面下部の「作成履歴」に出る（t06）。ボタンの近くに進行表示がなく、完成に気づきにくい。
  - 編集画面の「領域」が内部コード（`drug_therapy`）のまま表示（t04）。
  - 承認者も無効化された入力欄で内容を読む（t07）。患者画面と同じ見た目での確認は**公開後**にしかリンクがない（プレビュー画面自体は公開前も表示可能）。
  - 承認前に確認すべき点（未引用の段落、出典なし、原資料にない語）が画面上に要約されない。Day 5 の REPORT.md で行った点検が UI にない。
  - ファイル選択がブラウザ標準の英語表示（「Choose File」）、チェックボックスが 23px と小さい。

## デモ動画の観点
- 伝わる価値（この順に見せると自然）: ①患者が QR で共有 → ②医師が「今日の確認事項」で誤答と質問を把握 → ③テンプレートで数タップ処方 → ④患者がスマホで学習・確認 → ⑤次回診察で誤答から再処方 → ⑥教材スタジオで原資料から Claude が構成案を出し、医療者が原文と照合して承認。
- 撮影前に必要なこと: 開発用表示（擬似生成バナー、`clinician`、「後続フェーズ」等）を出さない、実 API で生成した教材をデモ用に用意、スタジオの構成案を画面内で見せる（P0-03）。
