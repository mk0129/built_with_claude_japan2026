## 1. 通し結果

生成 → 編集（タイトル変更）→ 提出 → 編集者は承認不可を確認 → 別の医師が承認・公開 → 患者へ処方 → 全画面学習 → クイズ完了 まで成功（E2E 1.4 分）。

## 3. 医学的確認が必要な項目（医師確認待ち）
1. **架空原資料そのもの**（開発者が作成）。特に:
   - LH-RH アゴニストの投与間隔「4週ごと、または12週ごと」（24週製剤の扱い）
   - 「ほてり・発汗・のぼせは、どの薬でも起こりやすい」という一般化
   - 大豆イソフラボン等サプリメントへの言及、ホルモンを含まない避妊法の記載
   - 5年基本・10年まで延長、子宮体がんリスク・血栓の表現
2. C 方式で「不正出血時に婦人科を受診」が落ちたことの臨床的な許容性
3. C 方式クイズが緊急症状（息苦しさ・胸痛・不正出血）を問わないことの許容性
4. 「骨密度（骨の強さ）」など AI が加えた言い換えの妥当性
5. 各問の誤答選択肢が患者に誤解を与えないか

## 4. 品質要件の確認
- 擬似と実生成の区別: ジョブに generator を記録、画面にバッジ（d5_04 の「Claude API」）。キーがあれば擬似設定より実生成を優先
- API 失敗・タイムアウト: スタブサーバーで TIMEOUT/529/500/401 を実 SDK 経路で検証、再試行・リース回収・上限到達を統合テストで確認（`tests/integration/claude-failures.test.ts`）
- 認証・権限・承認: 既存の統合テストを維持、E2E で編集者の自己承認不可を確認
- E2E の独立性: 毎回一時 DB・専用ポートで起動（`scripts/e2e-server.mjs`）
- Vercel のジョブ: `after()` は高速経路のみ。DB リース＋Cron 回収＋ポーリング時 nudge（`docs/day5/JOB_EXECUTION_DESIGN.md`）
