# shiori — 診察と診察のあいだを、つなぐ。

**患者が自分のことを理解し、医療者に伝え、共に次の一歩を考えられる。**

Built with Claude: Japan 2026 提出作品。扱うデータは**すべて架空**（患者・医療機関・医療者・教材）です。本番の医療運用を主張するものではありません。

- **審査用デモ（ログイン不要・架空データ）**: https://shiori-judge-demo.vercel.app/ — 入口で「患者として体験」「医療者として体験」を選びます。医療者側は共有前の状態から始まり、患者側で発行した 6 桁コードか、画面上の「デモ: 架空患者の共有を開始する」で診察を始められます。教材スタジオは既定では記録済みの Claude 出力を再生し、合言葉を入れた端末だけ実際に Claude を呼びます（鍵は配信側の環境変数だけが持ち、ブラウザには渡りません）。
- **デモ動画（3 分）**: 準備中（提出時に URL を記載）。
- **提出ブランチ**: `feat/submission-ux-redesign-20261108`（2026-11-08 の UI/UX 見直しを含む最新版）。

## 解決する課題
がんの治療中、患者が医療者と話せるのは数週間に一度、限られた診察時間だけです。
- **診察と診察のあいだ**: 説明を受けても自宅では思い出せない。体調の変化や疑問は、次の診察までに忘れてしまう。
- **診察の場**: 医療者は限られた時間で、患者がどこまで理解しているか、自宅でどう過ごしていたかを把握しきれない。記録や入力の負担も増やせない。
- **説明資料**: 患者向け教材の作成・更新には手間がかかり、内容の正確さと読みやすさの両立が難しい。

shiori は、医療者が届けた教材で患者が学び、日々の体調と質問を記録し、次の診察で患者自身の承認のもとに医療者と共有する ——「診察と診察のあいだ」を一つの流れでつなぎます。

## 主要機能
| | 患者（スマートフォン） | 医療者（iPad / PC） |
|---|---|---|
| 情報処方と学習 | 届いた教材を 1 画面 1 主題で学ぶ。理解確認（3 択＋「わからない」）。自分で教材を探して学ぶこともできる | 承認済み教材から処方。同じ診察で重複しない。前回の内容を見て追加処方 |
| 体調と質問の記録 | バイタル（任意・酸素投与量を含む）・自覚症状（自分で 0〜4。CTCAE を参考にした程度の目安つき）を何度でも記録。受けている治療から症状をまとめて設定。「聞きたいこと」に質問を保存し、聞けたら印を付ける | — |
| 一時共有 | 医療者の QR をカメラで読み、申請者と有効期間を確認して**自分で許可**。いつでも終了 | 共有中（60 分）だけ患者の記録を見られる。**患者一覧はない** |
| 診察サマリー | — | S・O（自覚症状・バイタル）→ 患者の質問・理解のつまずき → 理解確認の正答率と、**AI の情報処方リコメンド**（ルールベース → Claude が候補を絞る）。在宅経過表（目安の色分け・統合グラフ）と **Claude による外来間の要約**（各文から根拠の記録）。**閲覧だけで診察を終えられる** |
| 教材スタジオ | — | 原資料（許諾・個人情報なしを確認）→「Claudeで教材を作る」で構成と必須事項をすべて含めた下書きを 1 つ作成 → 医療者が編集・患者の見え方を確認 → 承認して公開（3 手順）。実行中は段階と所要の進行バー |

## 利用の流れ
1. **医療者**が教材スタジオで教材を作成・承認し、診察で情報処方する。
2. **患者**は自宅で教材を学び、わからなかったことは「わからない」と答える。体調と質問を記録する。
3. 次の診察で、**医療者**が QR を表示 → **患者**がスマートフォンで読み取り、内容を確認して共有を許可。
4. **医療者**は診察サマリーで、学習・回答・体調・質問を整理した外来間の要約を読み、気になる文から元の記録を確認する。必要なら教材を追加処方する。
5. 何も入力せずに共有を終了。医療者の画面から患者の情報は消え、以後は見られない。

## Claude の役割
| 場面 | Claude がすること | 人とシステムが担保すること |
|---|---|---|
| 教材の作成 | 許諾を確認した原資料から、構成・必ず含める内容の候補・本文と確認問題の下書きを作る（原資料の引用つき。必須事項はすべて含めて作り、編集画面に一覧で残す） | 原資料との照合、編集、医学的な承認は医療者。未承認の教材は患者に届かない |
| 外来間の要約 | 期間内の記録（体調・学習・回答・質問）を、日付と程度を添えて時系列に整理する。各文に根拠の記録 ID を付ける | サーバーが文ごとに、根拠の存在・数値・日時・件数・引用を元データと照合し、通らない文は表示しない。解釈や診断の語があれば要約全体を表示せず、ルールベースの要約に切り替える |
- Claude は**診断・CTCAE Grade の推定・因果関係の判断・治療の提案をしない**。欠測を「症状なし」「改善」と解釈しない。
- 外部 AI に送るのは**架空のデモ患者（@example.com）の構造化データだけ**（氏名・メールは送らない）。実患者の利用には施設の承認・データ処理契約・セキュリティ評価が別に必要で、この実装は送信しない。

## デモ方法
```bash
npm install
cp .env.example .env.local         # BETTER_AUTH_SECRET などを設定（.env* は Git に含めない）
npm run db:setup                   # ローカル DB（PGlite）を作成し、架空データを投入
npm run dev                        # http://localhost:3000
```
- Claude を使わずに動かすとき: `ANTHROPIC_API_KEY=` と `CLAUDE_FAKE=1`（開発用の擬似生成。画面に「Claudeではありません」と表示）。
- ログイン画面の架空アカウントを選ぶ: 医療者「佐藤 一郎」（診療・教材編集・承認。**架空の承認者**）、患者「伊藤 涼子」（履歴なし）・「佐藤 花子」（2 週間の記録あり）。

## 実装範囲
- **動くもの**: QR 一時共有（承認・60 分・延長の再承認・即時終了・6 桁コード）、情報処方と学習・理解確認、体調記録と聞きたいこと、治療の記録（がん種・治療・何日目）、在宅経過表と外来間要約（Claude ＋検証＋ルールベースの代替表示）、教材ライブラリ（AI 推奨の候補・セット・自作セット）、教材スタジオ（原資料 → 教材の編集 → 承認・公開）。
- **画面**: Figma Make で設計した UI（Concept D）をそのまま移植。患者 `/home`、医療者 `/staff`。
- **2026-11 の見直し**: 審査フィードバックに基づく UI/UX の再設計（患者ホームの 3 ブロック化、聞きたいことのストック管理、医療費シミュレーターの再設計、医療者の診察サマリーの SOAP 化と AI リコメンド）。内容と対応表: [`docs/review/ux_redesign_20261108/README.md`](docs/review/ux_redesign_20261108/README.md)。
- **未実装・今後**: 外来日の確定・登録（現在は期間を医療者が選ぶ）、医学図解の画像（差し込み口と一覧のみ）、通知、電子カルテ連携、実患者での利用に必要な体制。
- **技術**: Next.js 16 / React 19 / TypeScript、Drizzle ORM（PostgreSQL、ローカルは PGlite）、Better Auth、Anthropic Claude API（Sonnet 5.5・構造化出力）。テスト: Vitest（統合・認可・整合性・要約の検証）、Playwright（デモの通しを含む E2E）、Figma との画素比較。

## 医療安全上の制約
- 医療者が患者の情報を見られるのは、**患者が承認した有効な一時共有の間だけ**。医療者の患者一覧・恒久的なアクセス権はない。共有終了後は API が拒否する。
- 記録しても医療者へ通知しない。**24 時間の遠隔モニタリングではない**。緊急時は医療機関が指定する連絡方法を使うよう画面で案内する。
- 自覚症状の 0〜4 は患者本人による程度で、CTCAE Grade ではない。理解確認の点数で医学的な理解を断定しない。
- 教材は医療者の承認後にだけ患者に届く。**デモの教材・承認は架空で、本番の医学的監修を意味しない**。医学図解は監修（承認）済みのものだけ表示する。
- 実患者データ・権利を確認していない資料は使わない。
